# JLPT 루마 디자인 시스템

작성 2026-11-13 · **다시 그림 2026-11-16**(차분하고 단순하게: 크림 바탕, 흰 면, 먹색 프라이머리 하나, 파스텔 포인트; 홈의 두 버튼과 두 학습) · **2단계 2026-11-16**(화면마다 하나만 묻고, 보이는 글자는 이름표와 숫자뿐: 급수 고르기, 홈의 "오늘" 카드, 의미·히라가나를 따로 여는 학습 카드와 예문, 급수 색) · Astryx `@astryxdesign/core` **0.7.15** (베타, 정확한 버전으로 고정) · 테마 `ruma`

이 앱의 모양은 테마 `ruma` 하나에서 나옵니다. 테마는 Meta의 오픈소스 디자인 시스템 [Astryx](https://github.com/meta/astryx)(MIT)의 테마 형식으로 쓰고 Astryx CLI로 빌드하며, 결과는 **평범한 CSS 변수**입니다. 테마가 색·글자·간격·모서리·깊이·움직임의 **유일한 출처**이고, 앱의 CSS(`src/styles.css`)는 같은 토큰만 씁니다.

컴포넌트는 둘로 나뉩니다(9장의 측정으로 정함):
- **직접 만든 가벼운 컨트롤**(`src/components/ui.tsx`): 버튼, 아이콘 버튼, 묶음·행(`Group`·`Field`), 사실 줄(`Meta`), 결과 줄(`Result`), 세그먼트, 칩, 스위치, 검색칸, 진행 막대, 배너, 빈 상태, 스켈레톤. 처음 불러오는 묶음에 들어갑니다.
- **Astryx 컴포넌트**(`src/components/overlays.tsx`): 확인 대화상자(`AlertDialog`), 알림 대화상자(`Dialog`), 아래 시트(`BottomSheet`). 사용자가 열 때만 필요해서 **따로 불러오는 묶음**이고, 그 스타일도 함께 옵니다.

| `src/components/ui.tsx` | 화면마다 같은 일에 같은 컨트롤: 직접 만든 컨트롤 + 대화상자·시트의 지연 불러오기 래퍼(`Sheet`, `ConfirmDialog`, `MessageDialog`) |

CSS 층(@layer): `reset` → `astryx-base`(Astryx 기본 토큰, 대화상자·시트) → `astryx-theme`(ruma) → `app`(앱). 요소 선택자(`body`, `h1`, `a` …)는 `reset`에, 클래스 규칙은 `app`에 둡니다. 층 밖(unlayered)에는 마스코트 CSS 원본과 `native.css`용 옛 이름 별칭만 둡니다.

테마 모드: 설정의 시스템/라이트/다크가 `useThemeMode`로 `<html data-theme>`를 맞춥니다(시스템이면 속성 없음 → OS를 따름). `<html data-astryx-theme="ruma">`는 `index.html`에 고정되어 있어 첫 그림부터 테마가 적용됩니다. 라이트/다크 값은 토큰마다 `[라이트, 다크]` 한 쌍입니다. `syncTextSize`는 iOS의 글자 크기(Dynamic Type)를 읽어 `--_dynamic-type-*` 배율을 정하고, 테마의 `--font-size-*`가 그 배율을 따릅니다.

- **웹 글꼴은 받지 않습니다**(오프라인 우선). 모두 기기 글꼴입니다.

### 간격 · 모서리 · 크기 · 깊이 · 움직임

- 간격은 Astryx의 4px 단계: 화면 좌우 `--spacing-5`(20, 안전 영역보다 작지 않게), 카드 안 16, 한 묶음 안 12, 묶음 사이 24.
- 모서리: 16(`--radius-element`: 버튼·입력·세그먼트 바탕·읽기 선택지) · 12(`--radius-inner`: 세그먼트 칸, 작은 버튼) · 20(`--ruma-radius-card`: 묶음 카드·타일·평가 버튼·급수 버튼) · 24(`--radius-page`/`-container`: 학습 카드, 시트, 대화상자, 홈의 큰 버튼, 탭바 위 모서리) · `--radius-full`(칩, 태그, 연속 알약, 학습 카드의 토글, 결과 화면 루마의 원). 급수 고르기의 카드 22, 급수 배지 8(큰 배지 18), 한자 칩 16.
- 높이: 글자 버튼 48(`--ruma-control`) / 큰 버튼 52(`--size-element-lg`) / 홈의 큰 버튼 76(프라이머리)·64 / 평가 버튼 60 / 아이콘 버튼·글자 버튼 44(`--size-element-md`). 누르는 것은 모두 44 이상(칩·세그먼트 칸은 40 + 위아래 2px 보이지 않는 누름 영역).
- 깊이: **누를 수 있는 것에만** 아래 가장자리 — 큰 버튼 4px(`--ruma-depth`), 48px 버튼 3px(`--ruma-depth-sm`). 면은 1px 선(학습 카드만 `--shadow-low`의 아주 옅은 그림자). 그림자는 떠 있는 층(시트·대화상자·저장 실패 배너)과 탭바의 옅은 윗그림자에만.
- 움직임: 120/200/400ms, 곡선 하나(`--ease-standard`). 상태가 바뀔 때만 움직이고 반복 애니메이션은 화면당 하나(마스코트). **동작 줄이기**를 켜면 CSS 애니메이션·전환이 모두 꺼집니다.

### 두 학습 (2026-11-16)

홈의 두 버튼은 오늘의 카드를 둘로 나눈 **두 학습**을 엽니다. 나누는 곳은 큐를 만드는 한 곳(`srs.ts` `buildQueue(…, { mode })`, `StudyMode`)이고, 홈의 숫자와 학습 화면이 같은 함수를 부르므로 **버튼의 숫자 = 그 학습이 보여 주는 카드**입니다(`tests/unit/counts-agree.test.ts`).

| 경로 | 학습 | 들어가는 카드 |
| --- | --- | --- |
| `#/study/review` | 복습 | 오늘 몫의 복습 카드(하루 한도까지) + **다시 익히는 중인 카드**(복습에서 "모르겠어요"한 카드, FSRS 상태 Relearning) |
| `#/study/new` | 새 단어 | 오늘의 새 단어 + **처음 익히는 중인 카드**(새 단어로 들어와 아직 학습 단계에 있는 카드, 상태 Learning) |
| `#/study` | 전체(전과 같은 한 줄 큐) | 둘 다. 알림·위젯·예전 링크가 여는 경로 |

- **익히는 중 카드는 자기를 만든 학습에 속합니다.** 새 단어가 그날 만드는 학습 단계는 새 단어 학습에, 복습에서 잊은 카드의 다시 익히기는 복습 학습에 남습니다. 무엇에 속하는지는 카드의 FSRS 상태에서 읽으므로 **저장하는 것이 없습니다**(저장 형식 v4 그대로).
- 그래서 두 학습은 오늘의 카드를 **빠짐없이, 겹침 없이** 나눕니다: 전체 큐의 모든 카드는 둘 중 정확히 하나에 있고, 어느 학습도 열려 있는 동안 다른 학습에 카드를 빼앗기지 않습니다. 다른 학습의 익히는 중 카드는 이 학습에 나오지 않고 그쪽 버튼의 수에 남아 기다립니다(전날 끝내지 못한 Learning 카드도 새 단어 쪽: "익히는 중 n개 포함").
- 하루 계획은 **먼저 전체로** 세웁니다: 복습 한도와 밀린 복습(`held`), 밀렸을 때 새 단어를 5개로 줄이는 것까지 정한 뒤 다른 학습의 카드만 뺍니다. 그래서 두 학습의 수를 더하면 언제나 그날의 수이고, 알림·위젯·"오늘 n / m장"은 전과 같은 전체 수를 씁니다.
- 일정 계산(FSRS), XP, 연속, 되돌리기·다시 고르기, 백업은 바뀌지 않았습니다. 퀘스트 "오늘 분량 끝내기"(50XP)는 전처럼 **하루 전체**가 끝날 때 한 번입니다.
- 학습 화면의 결과: 이 학습은 끝났는데 다른 학습에 카드가 남았으면 "복습 끝" / "새 단어 끝"과 그 학습의 버튼("새 단어 n개" / "복습 n장", 프라이머리), 그리고 "홈으로". 하루가 다 끝났으면 "오늘 끝". 결과 화면의 "50장 더" / "새 단어 10개 더"는 그 카드가 속한 학습에서 이어집니다(다른 학습이면 그 경로로 넘어감).
- 넘겨 볼 수 있는 기록(`src/session.ts`)은 전처럼 학습 화면을 한 번 연 동안의 것입니다. 다른 학습을 열면 새 학습입니다.

- **두 토글은 따로 열립니다.** "의미"는 뜻, 뜻 다른 한자어 경고(유형 F), 예문의 번역, 한자 줄의 한국 한자음을 엽니다. "히라가나"는 표제어 위의 읽기, 예문 속 표제어의 후리가나, 한자 줄의 일본 읽기를 엽니다. 둘 다 이 카드에서만 기억합니다(다음 카드는 닫힌 채). 읽기가 없는 말(가나 말)에서는 히라가나가 꺼져 있습니다(`aria-disabled`).
- **아무것도 움직이지 않습니다.** 읽기 칸, 의미 칸, 번역 줄, 한자 줄은 닫혀 있어도 늘 자리를 차지하고(`visibility`), 열면 보이기만 합니다(동작 줄이기가 아니면 200ms 페이드). 그래서 표제어와 예문은 네 상태(닫힘 · 의미 · 히라가나 · 둘 다)에서 같은 자리에 있습니다(e2e `card.spec.ts`가 위치를 비교). 결과 줄과 토글도 한 칸에 겹쳐 놓아 카드 높이가 변하지 않습니다. 카드 안에는 선이 없고 간격으로만 나눕니다.
- **높이** — 모든 칸이 있는 카드(예문 두 줄, 한자 줄, 긴 뜻)는 390×844에서 들어오고, 320×568과 가장 큰 글자에서는 카드가 **안에서 스크롤**됩니다. 위의 막대와 아래의 평가 버튼은 화면에 남고, 무엇을 열어도 표제어는 뛰지 않습니다(내용의 높이가 상태마다 같으므로). 긴 뜻은 의미 칸 안에서 줄을 바꿉니다.
- **예문** — 문장은 `<ruby>`(후리가나 `rt`는 보조색, 약 10px, 줄 높이 2.1로 윗줄과 겹치지 않음). 문장은 카드 안에서 줄을 바꾸고, 한자보다 긴 읽기는 그 낱말을 넓힐 뿐 카드 밖으로 나가지 않습니다. 표제어를 찾는 규칙은 `src/examples.ts` `headwordSegments`(표제어의 마지막 한자까지 = 핵심, 그 핵심과 겹치는 조각들). 찾지 못하면 모든 조각의 후리가나가 보입니다. 예문이 없는 급수는 예문 칸이 없습니다. 데이터는 `data/examples/n5.json`(기계가 쓰고 기계로 검사함, `data/examples/README.md`)을 `scripts/build-data.mjs`가 검사해 `public/data/examples-n5.json`으로 내고, 앱은 그 급수의 카드가 처음 예문을 찾을 때 불러옵니다(`src/examples.ts`; 웹은 서비스 워커가 사전 캐시, iOS 앱은 묶음에 포함 → 오프라인).
- **한자 줄** — 표제어가 전부 음독이고 한자·한국 한자음·읽기 나눔(`a`)이 하나씩 맞는 말에만(`src/sound.ts` `kanjiParts`). 두 토글이 다 닫혀 있으면 자리만 있고 비어 있습니다.
- **평가는 처음부터 셋**: 모르겠어요 · **알아요**(먹색 프라이머리) · 쉬워요, 각 버튼 안 둘째 줄에 간격(`.grade-after`, 12px, `aria-hidden`; 이름은 "알아요, 4일 뒤 다시"). 높이 68px로 어느 상태에서도 같습니다. **알아요·쉬워요는 아무것도 열지 않고 눌러도 됩니다**(아는 단어는 빨리 넘김). **모르겠어요**는 전처럼 모든 칸을 열고 결과 줄("↻ 10분 뒤 다시 나와요")을 토글 자리에 보이며, 막대는 넓은 "다음" 하나가 됩니다(그것이 "모르겠어요"로 매김). 두 번 눌러도 350ms 안의 두 번째는 무시합니다.
- **누르는 것은 토글, 발음, 북마크뿐**입니다. 카드나 표제어를 눌러도 아무것도 열리지 않습니다(잘못 누름 방지). 단어 시트는 단어장·급수의 목록에서만 엽니다.
- **키** — Space/Enter: 두 토글을 엶(모르겠어요 뒤에는 "다음"). 1: 모르겠어요(그 뒤에는 다음), 2: 알아요, 3 또는 ↑: 쉬워요 — 무엇이 열려 있든. ←/→: 이번 학습의 앞/뒤 카드. 지난 카드에서는 1–3(읽기 카드 1–2)이 그때의 평가 버튼. 포커스된 버튼은 키보드로 옮겨 온 경우에만 자기 Enter/Space를 받습니다.
- **읽기 카드**(뜻 같은 한자어의 4지선다)는 흐름이 그대로입니다: 표제어 · "어떻게 읽을까요?" · 선택지 넷 · 모르겠어요 → 답하면 결과 줄, 다리("産業 = 산업 → さんぎょう"), 뜻, 한자음 대응, "다음"(간격 둘째 줄). 예문은 처음부터 보이되 표제어의 후리가나와 번역은 답한 뒤에. 토글은 없습니다.
- **지난 카드**(오른쪽으로 밀기, ←) — 모든 칸이 열린 채("이전 3/12"), 모든 후리가나·번역·한자 줄까지. 아래에 그때의 평가 버튼과 간격, 매긴 평가는 눌린 모양(초록 틴트 + 선 + ✓ + `aria-pressed`). 다른 평가를 누르면 다시 매깁니다(`session.ts`). 되돌리기는 지금 카드에서만. 넘기기는 `useSwipe.ts` 그대로(컨트롤에서 시작한 누름은 넘기기가 아님, 넘긴 끝의 클릭은 삼킴).
- **위** — 닫기, 진행 막대(말차), "n장 남음", 되돌리기. 답한 뒤 잠깐 "26일 뒤 다시 나와요".
- **결과 화면** — 색 있는 원 안의 루마(하루가 끝났으면 초록·두 눈, 아니면 노랑·한쪽 눈), 제목(오늘 끝 / 복습 끝 / 새 단어 끝 / "익히는 중 n장"), 기다릴 때만 "40분 뒤", 하루가 끝났는데 밀린 게 있으면 "밀린 n" 태그, 흰 타일 셋(본 카드 · 연속 학습 · 오늘 XP), 엄지 쪽 버튼. 이 학습만 끝나고 다른 학습에 카드가 남았으면 그 학습의 버튼("새 단어 5개" / "복습 12장", 프라이머리)과 "홈으로". 문장은 없습니다.

### 그 밖의 화면

- **단어장** — 세그먼트(검색 · 북마크 · 약한 단어), 유형 칩, 검색칸, 결과는 **흰 카드 하나 안의 행**(교과서체 표제어 위·읽기 아래 / 뜻 / 오른쪽에 사실 하나). "급수별 기억 상태"는 카드 안에 급수마다 한 줄(이름 · 단계 막대 · 만난 수), 목표 급수에는 굵은 먹색 "목표"(분홍은 N3의 색이라 쓰지 않음).
- **급수** — 기억 상태 카드(단계 막대 12px, 네 숫자), 단계·유형 칩, 단어 카드.
- **단어 시트**(단어장·급수에서만) — 급수 배지 + 사실 줄 + 닫기, 읽기 위에 표제어, 오른쪽에 원형 버튼 둘(발음, 북마크), 뜻(24), 유형 태그·뜻 다른 한자어·한자음 대응, 그 아래 예문(모든 후리가나와 번역).
- **기록** — 내용은 그대로(도장 여정, 기억 유지율 · 학습 시간 · XP, 7일 복습 예보, 학습 기록). 묶음은 흰 카드, 세 숫자는 흰 타일. 예보의 오늘 막대는 먹색, 나머지는 옅은 초록.
- **설정** — 묶음마다 제목 + 흰 카드. 백업 두 버튼은 나란히, "모든 기록 초기화"는 그 아래 옅은 빨강. "루마의 안내 다시 보기"는 팁과 함께 없어졌습니다.
- **탭바** — 흰 면, 위 모서리 24. 지금 탭은 굵은 먹색 라벨 + **분홍으로 채운 아이콘**, 나머지는 보조색 선 아이콘.
- **첫 화면(launch)** — `index.html`의 `#launch`: 바탕색 위 루마와 "JLPT 루마"(JLPT는 분홍 잉크). 색은 테마 CSS가 오기 전이라 `rumaTheme.ts` 값을 복사해 둡니다. iOS의 시작 이미지와 `LaunchBackground` 색은 `npm run ios:assets`가 같은 마크업·값으로 만듭니다(Linux에서 실행됨).
- **처음 실행** — 급수 고르기 하나뿐입니다(위). 루마의 한 번짜리 팁(간격 반복, 읽기 카드)은 루마의 말과 함께 없앴습니다. 저장된 `guide.done`의 `srs`·`reading`은 불러올 때 버립니다(`store.ts` `RETIRED_GUIDE`, 저장 형식 v4 그대로).

### 문구 (소유자 규칙)

**앱 전체**에 적용합니다. 바뀐 글자, 일부러 남긴 설명, **용어집**과 라벨 규칙은 [`docs/copy-inventory.md`](copy-inventory.md)에 있습니다. 새 글자를 쓰기 전에 그 용어집부터 봅니다.

1. **화면마다 하나만 묻고, 보이는 글자는 이름표와 숫자뿐.** 설명하거나 권하는 문장은 없습니다. 학습자가 이미 아는 것을 말하는 문장도 쓰지 않습니다.
2. **루마는 말하지 않습니다.** 그림(잠듦 · 한쪽 눈 · 두 눈)만 상태를 보여 줍니다.
3. **추임새·소리말·부사·강조어·칭찬말·느낌표 없음.** 효과를 위한 말줄임(…)도 쓰지 않습니다.

학습자를 지키는 정보(지우는 확인, 가져오기 오류, 저장 실패, 효과가 라벨로 드러나지 않는 설정의 한 줄, 비공식 앱 고지, 라이선스·법적 글)는 짧게 남깁니다. **화면 낭독기 이름은 자세하게**("복습 시작, 107장", "새 단어 이어서 하기, 12개 남음, 익히는 중 8개 포함", "밀린 복습 50장 더 하기", "연속 12일, 오늘 하면 13일", "오늘 127장 중 64장").

## 4. 규칙

**강조 단계** — 한 화면, 한 버튼 묶음에서:
1. `primary`(먹색 면): 묶음마다 **하나**. 복습(없으면 새 단어), 알아요, 다음, 결과 화면의 다음 학습(없으면 홈으로).
2. `secondary`(흰 면, 1px 선, 옅은 가장자리): 나머지. 새 단어, 모르겠어요, 쉬워요, 백업 내보내기.
3. `destructive`(옅은 빨강 면, 짙은 빨강 글자): 지우는 동작. 반드시 한 번 묻습니다(`ConfirmDialog`).
4. `ghost`: 아이콘 버튼, 되돌리기 칩. 글자 행동은 `ghost` + `text-action`(먹색 굵은 글자에 밑줄, 상자 없음): 50장 더 ›, 되돌리기, 백업하기.

**표면** — 크림 바탕 위에 흰 면.
- 면은 **흰색 + 1px 선**: 학습 카드·시트·대화상자(24), 묶음 카드·목록·타일(20). 떠 있지 않은 면에는 그림자를 두지 않습니다.
- **묶음 = 작은 제목 + 흰 카드 하나**, 그 안의 행은 1px 선으로 나눕니다. 카드 안에 카드 없음.
- **가장자리 띠 없음**: 둥근 것에 한쪽만 선을 긋지 않고, 어떤 것에도 한쪽 굵은 선을 긋지 않습니다(`tests/e2e/surfaces.spec.ts`가 모든 화면의 계산된 스타일로 검사).
- 잠깐 보는 상세는 `Sheet`, 결정을 묻는 것은 `ConfirmDialog`, 지속되는 문제는 `Banner`.

**파스텔** — 작은 곳에만, 뜻을 혼자 전하지 않게: 결과 화면 루마의 원(상태는 얼굴이), 태그("밀린 n", 유형), 진행 막대, 고른 탭의 아이콘(굵은 라벨이 함께), 고른 평가(✓와 `aria-pressed`가 함께), 켜진 스위치. 큰 면을 파스텔로 칠하지 않습니다.

**상태(답한 뒤)** — 카드의 면은 바뀌지 않습니다. 결과는 `Result` 한 줄, 물었던 줄의 자리에(`aria-live`). 표시(✓ ✕ ↻)가 앞에, 색은 글자에만.

**라벨** — 정적인 사실은 " · "로 이은 글자(`Meta`)이거나 작은 태그(유형, "밀린 n"). 목표 급수는 굵은 먹색 "목표", 단계는 글자 + 작은 단계색 점.

**글자** — 네 역할: 24/20 굵게(제목·숫자), 16 본문, 14 라벨, 12는 단위와 눈금에만. 숫자는 본문색.

**아이콘** — Lucide, **행동**(닫기·발음·북마크·되돌리기·뒤로·셰브런)과 **색 대신 상태를 말하는 표시**(✓ ✕ ↻ ⚠)에만.

**누름·초점** — 누르면 면이 가장자리로 내려앉고 옅은 누름 막이 덮입니다. hover 막은 마우스가 있는 기기에서만. 초점은 3px 먹색 링(`:focus-visible`). 비활성은 `aria-disabled`, 50%.

**접근성** — 누르는 영역 44px 이상, 대화상자는 Esc로 닫히고 연 버튼으로 초점이 돌아갑니다. 상태 변화는 `aria-live`/`role="status"`. 안전 영역은 `env(safe-area-inset-*)`. 320px에서 가로 스크롤 없음. 라이트·다크 모두 axe 위반 0(e2e).

## 5. 새 화면을 만들 때

1. 화면 루트는 `.page` 안(탭이 있는 화면) 또는 `.study`(전체 화면). 맨 위는 `header.top > h1`. 보이는 글자는 3장 "문구"의 규칙을 따릅니다. 새 사용자를 위한 따로 된 화면(온보딩)이나 설명은 만들지 않습니다: 물을 것이 있으면 그것 하나만 묻습니다(3장 "급수 고르기").
2. 묶음은 `<Group title id>`(section + `h2.group-title` + 흰 카드 `.group-body`), 행은 그 안의 요소(`Field`, `Switch`, 버튼 줄 …). 묶음 사이 간격은 `.page > .group`이 맡습니다. 카드 안에 카드를 만들지 않습니다.
3. 선택지 2~5개는 `Choice`, 많거나 길면 `ChipGroup`, 켜고 끄기는 `Switch`, 행동은 `Button`(프라이머리 하나), 아이콘만이면 `IconButton`(라벨 필수).
4. 묻기는 `ConfirmDialog`, 알림은 `MessageDialog`, 상세는 `Sheet`(늘 렌더하고 `isOpen`만 바꿈 — 닫힘 움직임과 초점 복귀). 새 Astryx 컴포넌트가 필요하면 `overlays.tsx`에만 가져오고 `npm run theme`(그 컴포넌트의 CSS가 `astryx-overlays.css`에 들어감). 다른 파일에서 `@astryxdesign/core/*` 컴포넌트를 가져오면 공통 기반(약 150KB gzip)이 처음 묶음으로 들어옵니다.
5. 비어 있을 때는 `Empty`(무엇이 비었는지 + 채우는 법이 화면에서 보이지 않으면 어떻게 채워지는지, `docs/copy-inventory.md`).
6. 새 CSS는 `@layer app` 안에, 값은 토큰만. 새 색이 필요하면 `rumaTheme.ts`에 토큰을 더하고 `npm run theme`, 대비 쌍을 `tests/unit/theme.test.ts`에 추가.
7. 390·320px, 라이트·다크, 동작 줄이기로 확인합니다.

## 7. 쓰지 않은 것과 이유

- **Astryx `Button`·`IconButton`·`Card`·`SegmentedControl`·`ToggleButton`·`Switch`·`TextInput`·`ProgressBar`·`Badge`·`Banner`·`EmptyState`·`Skeleton`**(전에는 썼음): 9장. 처음 묶음에 하나라도 있으면 공통 기반이 따라옵니다. 특히 `Switch`는 혼자 98KB(gzip)를 끌고 옵니다(툴팁·필드·스피너·국제화).
- **`Theme` 공급자**: 토큰은 CSS 변수라 런타임이 필요 없습니다. 공급자 자체가 27KB(gzip)이고 공통 기반을 처음 묶음으로 끌어옵니다. 하던 일(모드, Dynamic Type)은 `themeRoot.ts` 60줄.
- **`astryx.css` 전체**: 모든 컴포넌트의 스타일이 한 파일(gzip 41KB). 쓰는 부분만 뽑습니다(8장, `build-theme.mjs`).
- **`List`/`ListItem`**: 링크 두 줄에 23KB(gzip). 단어 행에도 쓰지 않습니다.
- **`DateInput`**: 달력 팝오버가 앵커 위치 지정(iOS 26 이상)에 기대고, iOS의 기본 날짜 휠이 더 낫습니다. 기본 `<input type="date">`를 토큰으로 스타일.
- **`Toast`**: 되돌리기는 엄지 근처에 머물러야 해서 화면 안 칩으로 둡니다.
- **`Tooltip`, `Text maxLines`**: 앵커 위치 지정이 필요하고 휴대폰에는 hover가 없습니다. 준비도의 목표 눈금 툴팁도 뺐었고, 2026-11-14 준비도 자체를 없앴습니다.
- **`MobileNav`, `AppShell`, `Layout`**: 서랍·데스크톱 구조라 하단 탭에 맞지 않습니다.
- **소스 빌드(`@astryxdesign/build`, StyleX)**: CSS를 줄이지만 그 CSS는 Vite를 거치지 않아 `light-dark()`가 남고(iOS 17.5 미만에서 색이 깨짐) 빌드가 1초→9초가 됩니다. 미리 빌드된 `astryx.css`에서 쓰는 규칙만 뽑는 쪽이 더 작고(대화상자·시트 14KB) 빌드도 그대로입니다.
- **기성 테마 패키지(`theme-*`)와 웹 글꼴**: 기성 테마의 글꼴은 Google Fonts에서 받아 오프라인과 맞지 않습니다.

## 8. 브라우저 · iOS

**최소 iOS: 16.4**(앱의 `IPHONEOS_DEPLOYMENT_TARGET`, 2026-11-14 소유자 결정, `docs/plan/10-ios-build.md` 결정 3).

- 처음 묶음(직접 만든 컨트롤)이 기대는 것: `@layer`(15.4), `:focus-visible`(15.4), `dvh`(15.4), `color-mix()`(16.2), `inset`·`aspect-ratio`(15), `appearance: none` 체크박스의 `::before`/`::after`(스위치), `ResizeObserver`(Dynamic Type). `text-wrap: balance/pretty`는 없어도 그만인 꾸밈입니다.
- 테마: `light-dark()`(17.5)는 Vite의 CSS 최소화기(Lightning CSS, 대상 safari16.4)가 `--lightningcss-light/dark` 변수 전환으로 바꿉니다. `astryx theme build`가 쓰는 `@scope`(17.4)는 `npm run theme`이 `:where([data-astryx-theme="ruma"])` 접두로 펼칩니다. 빌드 결과에 `light-dark(`·`@scope`가 없는지 업그레이드 때 확인합니다(10장).
- 대화상자·시트(Astryx): `<dialog>`(15.4), `:has()`(15.4), `@property`(16.4) — 16.4가 최소인 이유의 하나. `@starting-style`(17.5)·`transition-behavior: allow-discrete`(17.4)로 쓰인 나타나기 움직임은 16.4~17.4에서 빠질 수 있습니다(동작·초점은 그대로, 기기 확인 필요). 팝오버·앵커가 필요한 컴포넌트는 쓰지 않습니다.
- `requestIdleCallback`이 없는 Safari에서는 대화상자 묶음을 2초 뒤에 불러옵니다.
- 15.0~15.3은 `@layer`를 몰라 스타일 전체가 빠지므로 지원하지 않습니다. 16.4보다 높여야 할 기능은 쓰지 않았습니다.

## 10. Astryx 업그레이드

베타라서 **정확한 버전**으로 고정합니다(`package.json`: `@astryxdesign/core`, `@astryxdesign/cli`, `@stylexjs/stylex` 범위 없이. StyleX는 Astryx 런타임의 피어 의존성).

1. 변경 기록 확인: `node_modules/@astryxdesign/core/CHANGELOG.md`, `npx astryx blog`.
2. 올리기: `npm i -E @astryxdesign/core@<새 버전> @astryxdesign/cli@<새 버전>` (StyleX 피어 버전도 맞춤).
3. 코드모드 미리보기 → 적용: `npx astryx upgrade --from 0.7.15` → `npx astryx upgrade --from 0.7.15 --apply` (`--list`로 목록). 바뀌는 곳은 `overlays.tsx`와 `rumaTheme.ts`뿐이어야 합니다.
4. 테마와 뽑은 CSS 다시 빌드: `npm run theme`. 오래된 빌드 테마는 런타임이 고쳐 주지 않습니다. `astryx-overlays.css`의 규칙 수가 크게 변하면(지금 976개) 이유를 봅니다.
5. 확인: `npx tsc --noEmit`, `npm test`(대비·호환 검사 포함), `npm run test:e2e`(대화상자·시트의 초점·Esc·닫기 포함), `npm run build`·`build:native`, 출력 CSS에 `light-dark(`·`@scope (`가 없는지, 처음 묶음 JS에 Astryx가 없는지(`dist/assets/index-*.js`에서 `astryx` 검색), 390/320 라이트·다크 스크린숏(특히 대화상자·시트).
6. 아래 알려진 문제가 고쳐졌는지 보고, 고쳐졌으면 우회 코드를 지웁니다.

`build-theme.mjs`의 CSS 뽑기는 StyleX가 컴파일한 Astryx JS가 쓸 수 있는 클래스를 모두 문자열로 적어 둔다는 점에 기댑니다(동적으로 만든 클래스 이름은 없음). 이 전제가 깨지면 대화상자·시트의 스타일이 빠지니 5번 스크린숏으로 확인합니다.

- 0.7.15 `theme build`가 `isPressed` 같은 낙타 표기 상태를 `[data-is-pressed="isPressed"]`로 써서 맞지 않음 → 지금은 칩을 직접 만들어 영향 없음.
