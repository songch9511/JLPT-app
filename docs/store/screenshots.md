## 5. 다시 만들기

```sh
# 작업 트리가 다른 변경으로 빌드되지 않을 때: origin/main을 깨끗한 worktree로
git worktree add --detach /tmp/ruma-shots origin/main
ln -s "$PWD/node_modules" /tmp/ruma-shots/node_modules
node docs/store/capture.mjs --root /tmp/ruma-shots --out ./store-shots
# 작업 트리 그대로
node docs/store/capture.mjs --out ./store-shots
# 일부만: --only 01-home,03-false-friend   빌드 생략: --skip-build   포트 지정: --port 4400
```

- `npm run build`(웹 빌드) → `npx vite preview`(빈 포트 자동 선택) → Playwright Chromium(`PLAYWRIGHT_BROWSERS_PATH`의 것, `playwright install`은 하지 않음)으로 찍습니다. 뷰포트는 440×956·402×874 CSS px에 배율 3, `ko-KR`, `Asia/Seoul`, 시계 고정, 동작 줄이기 켬.
- **안정 단어 ID를 씁니다**(docs/plan/08 §7). 단어는 생성된 데이터 `public/data/words-n*.json`(행마다 첫 열이 ID, `w000`…)에서 표기로 찾고, 각 ID가 그 급수에 속하는지 생성된 표 `src/generated/word-ids.ts`의 `ID_RUNS`로 확인합니다(맞지 않으면 `npm run data`로 다시 만들라며 멈춤). 위치(`<급수>-<idx>`)로 ID를 만들지 않으므로 동결 파일 `public/data/n*.json`을 지워도(§7.6) 그대로 돕니다.
- 저장 키 `kasane.state.v4`, `kasane.meta`, 상태 버전 4, 카드 형식(`SCard`)을 그대로 씁니다. 이것들이 바뀌면 시드도 함께 고칩니다.

## 6. 알려진 한계

- **웹 빌드를 Chromium으로 찍은 것**입니다. iOS WKWebView와 글꼴 렌더링이 다를 수 있습니다(시스템 글꼴 스택이 Linux에서는 다른 한글 글꼴로 대체됨). 제출용 최종본은 TestFlight 빌드를 실제 iPhone이나 시뮬레이터(Xcode)에서 찍는 것이 정확합니다. 그때도 이 문서의 시드·상태를 그대로 쓰면 됩니다(시뮬레이터에서는 백업 파일 가져오기로 시드를 넣을 수 있음).
- iOS 상태 표시줄이 없습니다. Apple 문서는 상태 표시줄을 요구하지 않지만, 실제 기기 캡처로 바꾸면 위쪽에 들어갑니다.
- 앱 전용 설정(복습 알림·진동·발음 음성)과 위젯은 웹 빌드에 없어 찍지 않았습니다. 위젯을 1.0에 넣으면 기기에서 홈 화면 캡처 한 장을 7번으로 추가하는 것을 추천합니다(4.2 대응에도 도움).
- 기록 화면의 "누적 XP 174,670"이 402pt 폭에서 두 줄로 깨지던 것은 2026-11-14에 고쳤습니다(요약 숫자가 한 줄에 들어가도록 글자를 필요한 만큼만 줄임, 16px 아래로는 줄이지 않음). 기록 화면은 5번 자리 그대로 두었습니다. 순서를 바꾸려면 위 표와 캡션만 고치면 됩니다.
