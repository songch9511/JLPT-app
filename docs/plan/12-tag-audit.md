# 12. S·F 태그 독립 감사

작성 2026-11-14 · 대상: `data/tags/n*-*.json`의 S 3,489개, F 75개 (8,130단어 중) · 근거: `data/tags/LABELLING.md` R1–R10, `08-word-data.md` §3 · **태그는 하나도 바꾸지 않았다.**

## 결론

1. **S 정밀도 추정 99.9% (95% 신뢰구간 99.1–100%).** 층화 표본 600개 중 확실한 오류 1개(～中 じゅう). 감사자가 "확신 없음"으로 둔 5개까지 오류로 치면 **98.8% (97.5–99.5%)**. 03 결정 5의 "S 정밀도 95%" 기준은 어느 쪽으로 세어도 넘는다.
2. **학습자 영향**: 읽기 카드 3,489장 가운데 뜻을 잘못 가르치거나 헷갈리는 다리 단어를 보여 줄 카드는 **약 2장(상한 30장)**, 확신 없음까지 넣으면 **약 40장(18–88장)**. 표본 밖 전체 목록을 훑어 확실성이 높은 사례 4개(点々·享受·相違·工員)를 더 찾았으므로 실제 수는 이 범위의 아래쪽보다는 위에 있다고 보는 편이 안전하다.
3. **`sk`(한국 한자음)는 기계 검사에서 실제 오류 0개.** 글자별 음+두음법칙으로 설명되지 않는 46개는 모두 정당한 사례(구자체 음 40, 사이시옷 2, 본음·활음조 2, 합성어 안 두음 2)이고, 규칙 경계 1개(刺激 자극: 한국어는 刺戟로 씀)뿐이다. 신자체 함정(芸·予·欠·灯·台·弁·証·体 등)으로 잘못 읽은 단어도 0개다.
4. **F 75개는 전수 검토**: 맞음 71, F가 아님 1(相対), 판정은 유지하되 경고 문구가 뜻을 왜곡 1(風俗), 확신 없음 2(交替·得意). F의 잘못은 경고 한 줄이 더 붙는 정도라 해가 작다.
5. **원어민 검토 목록 28행**(`data/tags/audit/review.csv`, 한 시간 안). 위에서부터 "틀렸을 가능성 × 학습자에게 주는 해" 순이다.

**한계**: 감사자는 라벨러와 같은 계열의 모델이다. 한국어 화자의 감각(이 단어를 보통 성인이 아는가, 다리 단어가 다른 말로 먼저 읽히는가)은 모델의 판단이고, 그래서 "확신 없음"을 따로 셌다. 최종 판단은 원어민이 해야 한다.

### 1.2 독립 판정 표본 (`node scripts/audit/sample.mjs`, seed **20261114**)

- **S 600개**, 급수 × 모양(한 글자 / 두 글자 / 세 글자 이상 / 가나 포함) 20칸 층화. 급수 몫 = max(80, 비례 몫), 나머지는 N3·N2·N1에 비례(N5 80, N4 80, N3 136, N2 118, N1 186). 칸 안에서는 비례 배분하되 작은 칸은 최소 min(칸 크기, 8)개. 난수는 mulberry32, 칸마다 ID 정렬 뒤 Fisher–Yates. 칸별 N/n은 `sample.json`.
- **F 75개 전수**(400개 미만이므로).
- 판정은 표본을 `ko`·`en`·`sk`만 보이게 뽑아(`--print`) 기존 근거(LABELLING 예시·reviewed.json)를 보기 전에 내렸다. 기준: ① `sk` 단어가 보통 한국 성인이 알고 쓰는 말인가(고어·북한어·사전에만 있는 말이 아닌가), ② 핵심 뜻이 JLPT 수준의 일본어 핵심 뜻과 같은가, ③ 말맛이 비슷한가, ④ 다리 단어가 다른 한자의 같은 소리 말로 먼저 읽히지 않는가.
- 추정: 칸 가중치 N_h/n_h의 층화 비율, 신뢰구간은 Kish 유효 표본 크기(전체 502)에 Wilson 구간. 오류가 거의 없는 칸에서 정규 근사 분산이 0이 되는 문제를 피하려는 선택이다.

추가로 표본 밖 S 2,889개를 모두 한 번씩 훑었다(빠른 읽기, 체계적 판정 아님). 여기서 나온 18건은 검토 목록에 넣되 정밀도 추정에는 넣지 않았다.

## 3. 원어민 검토 목록과 고치는 법

- `data/tags/audit/review.csv` (UTF-8 BOM, 엑셀에서 바로 열림) — 28행: id, 단어, 읽기, 급수, 현재 k, sk, ko, 발견, 제안(k sk / ff), 확신도, 해, 이유, 태그 파일, 빈 `decision` 열. 우선순위 = 확신도 × 해. 맨 위 9행(확신 중 이상)이 핵심이다.
- `data/tags/audit/findings.json` — 전체 기계 결과 요약, 추정치, 표본 675개 판정, 발견 28건. 행 단위 기계 결과는 `mechanical.json`.

**받아들인 수정 적용(이번에는 하지 않음)**:
1. CSV `tag_file` 열의 파일(예: `data/tags/n2-8.json`)에서 그 ID의 값을 고친다. S → J면 `{"k":"J","sk":"점점","rt":"on"}`처럼 `sk`·`rt`는 남기고, → F면 `ff`를 R9 형식으로 넣는다(제안 문구는 형식 검사를 통과하게 썼다).
2. 같은 표기·읽기·접사 위치의 다른 항목도 같이 고친다(R10, 검사기가 잡는다). 예: おじさん 3개(w09f·w3qa·w40u)는 한꺼번에 정한다.
3. R3·R4·R5 고정 판정 단어(明日·叔父さん 등)는 `scripts/enrich/tags-schema.mjs`의 `FIXED`도 고쳐야 오류가 나지 않는다. 刺激처럼 유지하기로 한 경고성 항목은 `data/tags/reviewed.json`에 이유를 적는다.
4. 검사: `node scripts/enrich/validate-tags.mjs` (0 error여야 함; 지금은 0 error · 0 warning · 147 reviewed).
5. 앱 데이터 반영: `npm run data` (= `node scripts/build-data.mjs --extras`) 후 `public/data/words-n*.json` 커밋. 감사를 다시 돌려 수치를 갱신하려면 아래 명령.

## 4. 다시 돌리는 법

```
node scripts/audit/check-tags.mjs            # 기계 검사 → data/tags/audit/mechanical.json (--list sk|alt|shin|kana|ko|same|ff 로 행 출력)
node scripts/audit/sample.mjs                # 표본 다시 뽑기(같은 seed면 같은 표본) → sample.json; --print S|F 로 판정용 출력
node scripts/audit/report.mjs                # 판정(judgements.json) + 기계 결과 → findings.json, review.csv, 추정치
ENRICH_CACHE=<캐시> python3 -I scripts/audit/hanja-readings.py   # 글자 음·이체자 표 재생성(캐시 필요)
```

`judgements.json`은 손으로 쓴 판정이다. 표본에 있는데 여기 없는 ID는 "맞음"으로 센다. 원어민이 판정을 바꾸면 이 파일을 고치고 `report.mjs`만 다시 돌리면 된다.

## 5. 확인하지 못한 것

- **한국어 화자 직관에 기대는 판단 전부**: "보통 성인이 아는 말인가"(취주·습자·양품점·상등·회답·현청), "다리 단어가 다른 말로 먼저 읽히는가"(자위·불의·출장·작자), 말맛(운전수·순사·인민). 감사자가 모델이므로 확신 없음 19건(S 17, F 2)은 원어민이 정해야 하고, "맞음"으로 둔 판정에도 같은 한계가 있다.
- 감사자와 라벨러가 같은 계열 모델이라 **같은 맹점을 공유할 수 있다**. 신뢰구간은 표본 오차만 반영하고 판정자 오차는 반영하지 않는다. 원어민이 표본에서 무작위 50개를 따로 판정해 감사자와의 일치율을 재 보면 이 부분을 잴 수 있다.
- `ko` 열 자체(모델 번역)의 정확성, J·N·M 태그, `rt`는 범위 밖이다. 다만 읽다가 본 데이터 문제 두 가지: w4db `副`의 읽기가 `とりわけ`(取り分け의 오기로 보임), 目下(めした)의 `en`이 もっか의 뜻("at present").
