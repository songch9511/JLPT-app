# 03. 커리큘럼 · 대시보드 재설계 명세

작성 2026-11-13 · 대상 코드: `src/srs.ts`, `src/store.ts`, `src/data.ts`, `src/screens/{Home,Study,Level}.tsx`, `scripts/build-data.mjs`

## 결론과 추천

1. **대시보드의 첫 줄은 "시험날 기억할 것으로 예상되는 단어 수"로 바꾼다.** FSRS가 카드마다 이미 가진 안정도(S)와 마지막 복습 시각으로 시험 당일 아침의 회상 확률을 계산하고, 단어별로 더한다. "만난 단어 수"는 내린다.
2. **오늘의 계획은 그 지표에서 거꾸로 계산한다.** 사용자는 "하루 새 단어 N개" 대신 "하루 몇 분"을 정한다. 앱은 남은 날짜, 밀린 복습, 측정한 답변 속도로 오늘 복습 수와 새 단어 수를 정하고, "오늘 하면 시험날 예상 +n단어"를 보여 준다.
3. **새 단어는 무작위 순서가 아니라 빈도순으로 꺼낸다.** 시작할 때 "아는 단어 거르기"로 아는 단어를 건너뛰게 하되, 표본 검증을 거친 단어만 별도 표시(`src:'t'`)한 카드로 넣는다. 스케줄러와 준비도가 자기 보고 때문에 부풀지 않게 하기 위해서다.
4. **한국어 한자어와 뜻이 같은 단어는 뜻 대신 읽기를 묻는다.** 産業은 한국인에게 뜻이 보인다. 시험이 묻는 것은 さんぎょう라는 읽기(漢字読み)와 표기다. 반대로 뜻이 다른 한자어(工夫 ≠ 공부)는 경고를 달고 뜻 카드를 반드시 거친다.
5. **카드 방향은 단어당 하나가 아니라 "필요한 카드만" 만든다.** 뜻 카드(현재)에 더해 한자가 있는 단어에는 읽기 카드(자동 채점 4지선다)를 단다. 각 카드는 독립된 FSRS 카드다(`<id>` / `<id>:r`). 단어 수 대비 카드 수는 약 1.5배로 예상한다.
6. **첫 구현 단위는 "준비도 지표 + 새 홈 상단 카드"다.** 데이터나 상태를 바꾸지 않고 `srs.ts` 계산과 `Home.tsx`만 고친다. 12월 6일 시험(D-23)을 보는 현재 사용자에게 바로 도움이 되도록 **두 번째 단위는 시험 모드**로 한다.

정직성 원칙: 이 앱이 말할 수 있는 것은 "목록에 있는 단어를 시험날 몇 개 기억할지"뿐이다. 합격 확률은 말하지 않는다(§4.4).

## 2. 커리큘럼 모델

### 2.1 단어 순서: "빈도순 + 비용 보정"

- **신호**: 현대 일본어 코퍼스 빈도. 같은 급수 안에서는 자주 나오는 단어일수록 시험과 실생활 양쪽에 먼저 쓸모가 있다(Nation의 빈도 기반 어휘 교육 원칙. 단행본이라 링크는 출판사 페이지만: [Learning Vocabulary in Another Language](https://www.cambridge.org/core/books/learning-vocabulary-in-another-language/)).
- **소개 순서** `o`(급수 내 0부터): `f`(빈도) 내림차순. 동점이거나 빈도가 없으면 JMdict 우선순위 태그 순(news1/ichi1 > 그 외), 마지막으로 현재 idx 순으로 정렬한다.
- **주제 묶음은 하지 않는다(소개 순서 기준).** 같은 의미 범주(색깔·요일·가족)의 새 단어를 한꺼번에 배우면 서로 간섭해 오히려 느려진다는 연구가 있다([Tinkham 1997, Second Language Research](https://journals.sagepub.com/doi/10.1177/026765839701300203), [Erten & Tekin 2008, System](https://doi.org/10.1016/j.system.2007.09.006). DOI는 기억에 의존했고 링크 미확인). 주제 정보는 나중에 단어장 필터 용도로만 쓴다(증분 밖).
- **하위 급수 포함(P4)**: 준비도 대상은 목표 급수와 그 아래 급수 전체(누적)로 하고, 하위 급수 단어는 "아는 단어 거르기"로 빠르게 정리하게 한다. 결정 항목 2.

### 2.3 단어별 새 데이터 필드

`public/data/n{l}.json` 행은 지금 `[w, r, ko, en]`이다. **뒤에 열을 덧붙이기만 한다**(idx 불변, P2).

| 필드 | 타입 | 뜻 | 만드는 법 |
| --- | --- | --- | --- |
| `o` | number | 급수 내 소개 순서 | `build-data.mjs`에서 `f`·JMdict 태그로 정렬해 순위를 매긴다. 행 순서는 그대로 둔다. |
| `f` | number (Zipf×10, 정수, 0=없음) | 빈도 | 새 스크립트 `scripts/enrich/freq.py`가 `wordfreq.zipf_frequency(w, 'ja')`를 호출한다. `〜`·`～`를 지우고, 표제어로 없으면 읽기로 다시 찾는다(동음어 오염 가능성이 있으므로 이 경우 값을 0.8배). 결과는 `data/freq/n{l}.json` `{idx: f}`에 저장해 저장소에 넣는다(빌드 때 Python 불필요). |
| `k` | `'S'│'F'│'N'│'L'│'K'` | 한국어 기준 단어 유형. S=뜻이 통하는 한자어, F=한자는 같지만 뜻이 다른 한자어(가짜 친구), N=고유어·훈독·혼종, L=가타카나 외래어, K=가나 고유어 | 아래 2.4 |
| `sk` | string | 한국 한자음(예: 産業 → `산업`) | 아래 2.4. 뒷면 힌트로만 쓴다. |
| `ff` | string? | F일 때 주의 문구(예: `한국어 '공부'와 달리 '궁리·고안'`) | 모델 생성 + 사람 검수 |

`data.ts`의 `Word`에 `o, f, k, sk, ff?`를 추가하고 `loadLevel`의 행 구조 분해를 늘린다. JSON 크기 증가는 행당 약 15바이트로 추정한다.

### 2.4 한국어 한자어 판별 (`k`, `sk`)

1. **후보 한자음 생성**: 한자만으로 된 표제어(N5 320개, N4 312개, N3 1,338개, N2 990개, N1 1,684개. 이 저장소 데이터로 직접 셈)마다 한자별 한국 한자음을 이어 붙인다. 출처는 KANJIDIC2의 `korean_h` 읽기([KANJIDIC 프로젝트](https://www.edrdg.org/wiki/index.php/KANJIDIC_Project), EDRDG 라이선스. 단, KANJIDIC의 빈도 번호 필드는 상업 이용에 별도 허락이 필요하다고 하므로 쓰지 않는다)다. 대안은 Unicode Unihan `kHangul`(Unicode 라이선스, 이 세션에서는 접속 차단으로 미확인)이다. 독음이 여럿이면 조합을 최대 8개까지 만들고 **두음법칙**을 적용한다(料理 료리→요리, 旅行 려행→여행).
2. **자동 S 판정**: 후보 중 하나가 `ko` 뜻 문자열에 단어로 들어 있으면 S로 정한다. 예: 産業 → `산업` ∈ "산업" → S. (`ko`도 모델 번역이므로 두 번째 확인 단계가 필요하다.)
3. **나머지 한자 표제어**는 모델에 일괄 분류를 맡긴다(입력: w, r, sk 후보, ko. 출력: S/F/N과 F일 때 `ff`). **F 판정은 전부 사람이 검수한다**(수백 개 이하로 예상, 미측정). 대표 예: 工夫(공부≠고안), 勉強(면강≠공부), 大家(대가≠집주인), 迷惑(미혹≠폐).
4. 가타카나만이면 L, 가나만이면 K로 정한다.
5. 품질 측정: 무작위 50개를 사람이 확인해 S 정밀도를 기록한다. 95% 미만이면 2단계 규칙을 고친다.

**취급 차이** (근거: 한·일 동형 한자어는 음운 유사성이 어휘 처리를 돕는다는 보고가 있다 — [히로시마대 연구](https://ir.lib.hiroshima-u.ac.jp/41632/files/21206). 다만 "한국인의 일본어 한자어 학습량이 줄어든다"를 직접 비교한 통제 연구는 찾지 못했다 → 효과 크기 **미확인**, 출시 후 데이터로 확인):

| k | 만드는 카드 | 새 단어 비용(예산 계산용) | 뒷면 |
| --- | --- | --- | --- |
| S | 읽기 카드만 (뜻 카드 없음) | 0.5 | 뜻 + `sk` 힌트 "한국어 '산업'과 같아요" |
| F | 뜻 카드 먼저, 졸업(state=Review) 후 읽기 카드 | 1.3 | 빨간 칩 "한국어와 뜻이 달라요" + `ff` |
| N, K, L | 뜻 카드. N은 졸업 후 읽기 카드 추가 | 1.0 | 현재와 같음 |

### 2.5 아는 단어 거르기 (배치 테스트)

목표는 아는 단어를 빨리 건너뛰되, **자기 보고가 스케줄러와 준비도를 부풀리지 않게** 하는 것이다.

흐름 (새 화면 `#/triage/<level>`, 온보딩 끝과 홈의 보조 링크에서 진입):
1. 급수 단어를 `o` 순서대로 20개씩 보여 준다(표제어만, 읽기·뜻은 숨김). 사용자는 **"확실히 아는 것만"** 탭한다. 기본값은 모름이다.
2. 한 페이지가 끝나면 탭한 단어 중 무작위 3개(탭이 3개 미만이면 전부)를 **자동 채점 4지선다**로 확인한다(S는 읽기, 그 외는 뜻. 오답 보기는 같은 급수 같은 품사에서 뽑음). 틀린 단어는 "모름"으로 되돌린다.
3. 검증 정확도 `q = 맞힌 수 / 확인한 수`(누적)를 계산한다. `q < 0.7`이면 "생각보다 헷갈리는 단어가 많아요. 거르기를 멈추고 차근차근 배울까요?"를 띄운다.
4. **멈춤 규칙**: 한 페이지에서 아는 단어가 30% 미만이면 "여기부터는 새로 배우는 게 빨라요"를 띄우고 끝낸다. 빈도순이므로 사실상 "아는 범위의 경계"를 찾는 셈이다.
5. **결과 반영**:
   - 확인을 통과했거나 표본에 뽑히지 않은 "앎" 단어 → FSRS 카드 생성: `scheduler.next(empty, now, Rating.Easy)`(초기 안정도 w3 ≈ 8.3일)를 쓰되, `due`를 **향후 28일에 하루 최대 15장으로 고르게 분산**한다. 늦은 복습은 FSRS가 경과일로 처리하므로 모델이 깨지지 않는다. 카드에 `src: 't'`를 붙인다.
   - S 단어는 읽기 카드로 생성한다(뜻은 앎으로 간주).
   - 거른 단어 목록은 단어장에서 "확인 전" 필터로 보여 주고 되돌릴 수 있게 한다.
6. **준비도 반영**: `src:'t'`이고 아직 실제 복습이 없는(`reps === 1`) 카드는 FSRS R 대신 `min(R, q)`를 쓴다. 첫 실제 복습 뒤에는 `src`를 지운다.

## 3. 카드 유형

JLPT 어휘 문항은 漢字読み(한자 읽기), 表記(표기), 文脈規定(문맥), 言い換え類義(바꿔 말하기), 用法(용법) 유형으로 구성된다(급수별 구성은 공식 문제 예시로 확인 필요 — **미확인**, jlpt.jp 접속 불가). 우선순위는 이 문항 유형과의 대응, 구현 비용, 자동 채점 가능 여부로 정했다.

| 순위 | 유형 | 앞 → 뒤 | 채점 | 대응 문항 | 대상 |
| --- | --- | --- | --- | --- | --- |
| 1 | **뜻** (현재) | 表記 → 뜻 | 자기 채점 | 文脈規定, 言い換え | k ≠ S |
| 2 | **읽기** | 漢字表記 → 4지선다 가나 | 자동 | 漢字読み | 한자 포함 단어(S는 첫 카드) |
| 3 | **듣기** | TTS 음성 → 뜻 4지선다 | 자동 | 청해의 기반 | 읽기가 급수 안에서 유일한 단어만(きかい 機会/機械 같은 동음어 제외) |
| 4 | **표기** | 가나 → 4지선다 한자 | 자동 | 表記 | 한자 단어 중 졸업한 것 |
| 5 | 문맥 빈칸 | 예문 → 단어 | 자동 | 文脈規定 | 예문 데이터 필요(Tatoeba CC BY 2.0 FR 등 — 라이선스 미확인) |
| 6 | 역방향 타이핑 | 뜻 → 가나 입력 | 자동 | 직접 대응 없음 | 휴대폰 가나 입력이 번거로워 선택 기능으로만 |

**읽기 오답 보기 생성**(일본어 음운 기반 규칙, 결정적): 장음 추가/삭제(さんぎょう↔さんぎょ), 탁음 토글(か↔が), 촉음 토글(っ), 요음 토글(きょ↔きよ), 같은 급수의 비슷한 길이 읽기 하나. 정답과 같은 보기를 빼고 3개를 뽑는다. 한국인이 실제로 틀리는 지점(장음·탁음)을 겨냥한다.

**FSRS 대응 방식 비교**

| 방식 | 장점 | 비용 |
| --- | --- | --- |
| A. 단어당 카드 1장, 유형을 번갈아 출제 | 복습량 그대로 | 서로 다른 기억(뜻/읽기)을 한 안정도에 섞는다. 읽기를 틀리면 뜻 간격까지 무너진다. |
| B. 단어×유형마다 독립 카드 | 모델이 깨끗하다 | 복습량이 유형 수만큼 늘어난다. |
| **C. 독립 카드, 단 필요한 유형만 + 형제 카드 묻기 (추천)** | 모델이 깨끗하고, 카드는 단어당 약 1.5장 | 키 체계·통계 수정 필요 |

C의 규칙:
- 카드 키: 뜻 카드는 기존 키 `<l>-<idx>` 그대로(마이그레이션 불필요). 읽기 `:r`, 듣기 `:l`, 표기 `:w` 접미사. `levelOf(id)`는 첫 글자만 보므로 그대로 동작한다.
- 형제 묻기(bury): 같은 단어의 다른 카드는 같은 날 한 장만 보여 준다. 나머지는 `due`를 다음 날 0시로 민다.
- 단어 단위 통계: `breakdowns`, `stageOf`, 단어장 점은 **단어 기준**으로 바꾼다. 단계는 그 단어 카드 중 가장 낮은 단계로 정한다.
- 비용 추정: 읽기 카드가 붙는 단어 비율은 한자 포함 단어 약 80%(N5 563/718). 그중 S는 뜻 카드가 없으므로 전체 카드 수는 단어당 약 1.5장으로 본다(S 비율 측정 전 추정).

## 4. 준비도 지표 (대시보드의 중심)

### 4.1 정의

- `T` = 시험일 09:00(현지). 카드 `c`의 시험날 회상 확률은 FSRS-6 망각 곡선으로 구한다([ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs) 구현으로 확인. [FSRS 알고리즘 설명](https://github.com/open-spaced-repetition/fsrs4anki/wiki/The-Algorithm)은 이 세션에서 직접 열람하지 못함):
  `R_c(T) = (1 + F · t/S)^(−w20)`, `t = T − last_review`(일), `F = 0.9^(−1/w20) − 1`, 기본 `w20 = 0.1542`.
  코드: `scheduler.get_retrievability(toCard(c), T, false)`. (설치본으로 확인: S=2.31, t≈31일 → 0.664)
- 단어 `w`의 확률 `p_w(T)`: 카드가 없으면 0. 있으면 그 단어 카드들 R의 **최솟값**("뜻도 읽기도 맞혀야 아는 단어". 실제로는 양의 상관이 있어 보수적 추정이다). `src:'t'` 보정은 §2.5-6을 따른다.
- 대상 집합 `W` = 목표 급수(+ 결정 항목 2에 따라 하위 급수).
- **현재 기준** `E_now = Σ_w p_w(T)`: 지금부터 아무것도 안 하면 시험날 기억할 단어 수.
- **계획 기준** `E_plan` = 계획대로 공부했을 때의 값. 두 부분의 합이다.
  1. 기존 카드: `due < T`이면 한 단계 앞을 내다본다. `rec = scheduler.repeat(card, due)`, `r = R_c(due)`. 그러면 `p = r · R(T; rec[Good]) + (1 − r) · R(T; rec[Again])`이다. `due ≥ T`이면 `R_c(T)`.
  2. 앞으로 소개할 단어: 계획(§5)이 `d`일 전에 소개할 단어 수 × `P_NEW[d]`. `P_NEW`는 기본 매개변수로 오프라인 몬테카를로를 돌려 만든 표다(새 스크립트 `scripts/sim-pnew.mjs`. 소개일 d = 1…180에서, 각 복습의 성공 확률을 그 시점 R로 두고 1,000회 시행한 평균). 결과는 `src/pnew.ts` 상수로 넣는다.
- **보정**: 복습 답변마다 예측 R을 `DayLog.e`에 더한다. 최근 30일 `실제 정답률 p/r`이 `e/r`보다 5%p 넘게 낮으면 모든 p에 `(p/r)/(e/r)`를 곱하고 "실제 기억률이 예측보다 낮아 보정했어요"를 표시한다.

### 4.2 상태 판정과 목표

- 목표 `G = ⌈goal · |W|⌉`, 기본 `goal = 0.8`. 이 80%는 **제품의 선택**이지 합격선에서 나온 숫자가 아니다(결정 항목 4).
- `E_plan ≥ G` → **순항** · `E_plan ≥ 0.9G` → **빠듯** · 그 아래 → **위험**.
- 실제 복습 답변이 30개 미만이면 상태를 판정하지 않고 "아직 판단하기 일러요"를 표시한다.
- 시험일이 지났거나 없으면 지표 대신 "다음 시험일을 골라 주세요"를 보여 준다.

### 4.3 "오늘의 계획"이 지표에서 나오는 방식

- `gain(today) = E_plan(오늘 계획 수행) − E_plan(오늘 건너뜀)`. 건너뛰는 경우는 기존 카드의 lookahead 시점을 내일로 옮기고 오늘 소개분을 빼서 계산한다. 화면 문구: "오늘 하면 시험날 예상 **+9단어**".
- 미달일 때 레버를 하나만 제안한다. 예산을 5분 단위로 올려 `E_plan ≥ G`가 되는 최소 분을 찾아 "하루 25분이면 목표에 닿아요 [바꾸기]". 45분에서도 안 되면 "목표를 70%로 낮추거나 다음 시험(2027-07-04)으로 미루는 것도 방법이에요"를 보여 준다.

### 4.4 무엇을 말할 수 없는가 (화면에 그대로 노출)

- JLPT는 N1~N3이 3과목(각 0~60, 과목 기준점 19, 총점 합격선 N1 100·N2 90·N3 95/180)이고, N4·N5는 언어지식(문자·어휘·문법)·독해(0~120, 기준점 38)와 청해(0~60, 기준점 19)로 나뉜다(합격선 N4 90·N5 80/180). 출처: [jlpt.jp 결과 안내](https://jlpt.jp/e/guideline/results.html). 검색 결과로 확인했고 원문은 접속 불가였다. 어휘는 그중 한 과목의 일부다.
- 그래서 앱은 **합격 확률을 표시하지 않는다.** 표시 문구: "N4 목록 단어 중 시험날 기억할 것으로 예상되는 수예요. 문법·독해·청해는 포함되지 않아요. 단어 목록은 비공식이에요."
- 자기 채점(뜻 카드)은 과대 보고될 수 있다. 자동 채점 카드(읽기·듣기·표기)가 늘수록 추정이 정직해진다.
- FSRS 기본 매개변수는 이 앱 사용자에게 맞춰진 값이 아니다. 개인 최적화는 기록이 수백~천 건 이상 쌓인 뒤에나 의미가 있다(결정 항목 6).

## 5. 세션 설계

### 5.1 예산과 하루 분량

- 설정 `budgetMin ∈ {10, 20, 30, 45}`(기본 20)가 `dailyNew`를 대신한다. `dailyNew`는 "직접 지정"(고급)으로 남긴다.
- 측정: `DayLog.ms`(카드 표시부터 답변까지의 활성 시간 합. 한 장에 60초 넘게 걸리면 60초로 자름). 답변당 초 `a = Σms/Σc`(최근 14일, 답변 50개 미만이면 8초).
- 새 단어 하나의 오늘 비용 `n = 3a × 비용계수(k)`(학습 단계 3회).
- 계산 (매 세션 시작 시 `planToday(s, now)`):
  ```
  cap        = ⌊budgetMin·60 / a⌋                       // 오늘 처리 가능한 답변 수
  dueRev     = due < 오늘 끝인 복습 카드 수
  revToday   = min(dueRev, cap)
  cutoff     = T − 14일 (시험 모드 시작)
  daysLeft   = max(1, cutoff까지 남은 날 − 남은 쉬는 날)
  needNew    = ⌈남은 미소개 단어 / daysLeft⌉
  roomNew    = ⌊(budgetMin·60 − revToday·a) / n⌋
  newToday   = clamp(min(needNew, roomNew), 0, 40)
               단 dueRev > cap(밀림) 이면 newToday = min(newToday, 5)
               쉬는 날이면 0, 시험 모드면 0(§5.4)
  ```
- "새 단어 10개 더 하기"는 시험 모드가 아니고 밀림이 없을 때만 보여 준다.
- P9의 "하루 100개로 맞추기" 버튼은 없앤다.

### 5.2 큐 순서

1. 지금 할 학습/재학습 카드(`due ≤ now`).
2. 복습과 새 단어를 섞는다. 새 단어는 `⌈revToday / newToday⌉`장마다 한 장씩 넣되, **학습 중 카드(state 1·3)가 8장 이상이면 새 단어를 미룬다**(한 번에 붙잡는 새 기억의 상한). 섞어서 내는 것 자체는 인출 연습과 간격의 이점을 살리는 방향이다([Roediger & Karpicke 2006](https://doi.org/10.1111/j.1467-9280.2006.01693.x), [Karpicke & Roediger 2008, Science](https://doi.org/10.1126/science.1152408)). 교차(interleaving)의 근거는 주로 수학·범주 학습에서 나왔고 단어 학습에서는 결과가 섞여 있다([Rohrer & Taylor 2007](https://doi.org/10.1007/s11251-007-9015-8)) → 이 규칙의 효과는 **미확인**으로 둔다.
3. 복습 순서: 평소에는 `due` 순. 밀렸을 때와 시험 모드에서는 **준비도 이득 순**, 즉 `gain_c = p(오늘 복습) − p(복습 안 함)`(§4.1 lookahead)의 내림차순. "밀린 카드는 R 오름/내림 중 무엇이 좋은가"에 대한 공개 비교는 확인하지 못했다(미확인). 그래서 앱의 목표 지표에 직접 맞추는 쪽을 택했다.
4. 새 단어는 `o` 순서. 같은 세션에 `ko` 첫 뜻이 같은 단어 두 개가 연달아 오지 않게 한 칸 민다(간섭 회피).
5. **세션 끝(P7)**: 남은 게 학습 카드뿐이면 "남은 3장 지금 마무리" 버튼으로 기다리지 않고 바로 보여 준다. FSRS-6은 같은 날 짧은 간격 복습도 모델링하므로 문제가 없다.

학습 단계는 ts-fsrs 기본값(`1m, 10m` / 재학습 `10m`)을 유지한다. "고정"이 문제였던 이유는 단계가 아니라 하루 분량이었다(5.1에서 해결). 단계 조정은 개인 최적화(결정 6) 때 함께 본다.

### 5.3 빠진 날 이후 (벌주지 않는 밀림 처리)

- FSRS는 늦은 복습을 경과일 그대로 계산하므로, 늦게 하는 것 자체로 모델이 틀어지지는 않는다.
- 밀림(`dueRev > cap`)이면 오늘은 `cap`장만 준비도 이득 순으로 내고, 나머지는 날을 넘긴다. 홈 문구: "밀린 복습 132장 — 오늘 40장, 나흘에 나눠 정리해요. 중요한 것부터 골랐어요."
- 연속 학습은 §6의 쉼표 규칙으로 보호한다. "다 끝내야 한다"는 압박 대신 "오늘 분량"을 끝내면 완료다.

### 5.4 시험 모드 (D-14부터 자동, 설정에서 끌 수 있음)

근거: 최적의 복습 간격은 기억을 유지해야 하는 기간의 일정 비율이다(시험까지 몇 주면 약 20%, 1년이면 약 5% — [Cepeda et al. 2008](https://pubmed.ncbi.nlm.nih.gov/19076480/)). 시험이 2주 남았으면 마지막 복습은 시험 며칠 전이 좋다.

- **새 단어 중단**: 시험 2주 전부터는 새로 배운 단어가 시험날까지 충분히 굳기 어렵다. `P_NEW`로 보면 같은 시간을 기존 단어 복습에 쓰는 편이 이득이 크다. 사용자가 원하면 "남은 고빈도 단어 훑기"를 할 수 있다. 이건 뜻 카드만 쓰고, 준비도 화면에 "기대 효과 작음"을 붙인다.
- **최종 점검 목록**: `R_c(T) < 0.85`이면서 `due ≥ T`인 카드다. 이것을 D-10~D-2에 하루 `cap`의 절반 이하로 나눠 `due`를 당긴다. 순서는 `R_c(T)` 오름차순이다.
- **약한 단어(leech, lapses ≥ 2)**: 매일 최대 10장을 읽기·뜻 둘 다 낸다.
- **D-1**: 계획은 약한 단어와 최종 점검 잔여만, 10분 이내. 문구: "오늘은 가볍게. 내일 잘 봐요."
- **D-day**: 계획 없음. 문구 "오늘은 시험날! 다녀오면 다음 목표를 정해요."
- **시험 후**: 다음 시험일과 급수를 묻는다. 카드 상태는 유지한다.

## 6. 동기 장치 검토

원칙: **정직하게 "모르겠어요"를 누르는 것이 손해가 되면 안 되고, 빨리 탭하는 것이 이득이 되면 안 된다.** 보상은 "오늘 계획 완료"와 "시험날 예상 단어"에 묶는다(시험날 예상 단어는 거짓 "알아요"로 부풀릴 수 있으므로 자동 채점 카드 비중을 늘려 견제한다).

| 요소 | 결정 | 이유 · 변경 내용 |
| --- | --- | --- |
| XP(카드당 10) | **변경**: HUD에서 내리고 기록 화면으로 옮긴다. 카드당 XP는 유지하되 하루 상한 = 오늘 계획 답변 수 × 10 | 답과 무관하게 주는 건 정직성 면에서 맞다. 하지만 장수에 비례하니 "더 많이 넘기기"를 부추긴다. 상한을 두면 계획 이상 넘기는 보상이 사라진다. |
| 레벨 | **제거**(기록 화면에 누적 XP만) | 시험 준비와 무관한 두 번째 진척 축이 첫 화면을 다툰다. |
| 퀘스트 3개 | **변경**: "오늘 계획 끝내기" 하나만 남긴다. 나머지 둘은 제거 | "20장 넘기기"는 탭 속도, "새 단어 10개"는 밀림 무시(P11). |
| 연속 학습 | **유지 + 쉼표 규칙** | 지속은 간격 반복의 전제다. 규칙: ① "학습한 날" = 오늘 계획의 50% 이상 또는 답변 20개 이상. ② 7일마다 쉼표 1개가 자동으로 생기고 최대 2개까지 쌓인다. 빠진 날에 자동으로 쓰여 연속이 끊기지 않는다. ③ 설정의 "쉬는 요일"은 연속에 영향이 없고, 계획에서도 빠진다. |
| 도장 여정(50단어 '만남') | **변경**: 도장 = 시험날 예상 기억 50단어마다. 한 번 찍은 도장은 지우지 않는다(최고치 `bestE` 기록) | 만남이 아니라 기억에 보상한다(P10). 지표가 내려가도 도장은 남기되 현재 위치 표시는 실제 값을 따른다. |
| 다루마 채우기 | **유지** | 오늘 계획 진행률에 묶여 있어 정직하다. 기준을 "오늘 큐 전체"에서 "오늘 계획"으로 바꾼다. |
| 히트맵 · 7일 예보 · 유지율 | **기록 화면으로 이동** | 유지율은 §4.1 보정 상태와 함께 보여 준다. |

## 8. 상태 구조와 마이그레이션

`localStorage` 키 `kasane.state.v2`는 **그대로 둔다**(키를 바꾸면 이전 데이터를 못 찾는 사고가 날 수 있다). 내부 `v`를 3으로 올리고 `load()`에서 이관한다.

```ts
interface SCard { /* 기존 필드 */ src?: 't' }                 // 거르기로 생성, 첫 실제 복습 후 삭제
interface DayLog { /* 기존 */ ms?: number; e?: number; rest?: 1 } // 활성 시간, 예측 R 합, 쉼표 사용
interface State {
  v: 3
  settings: { /* 기존 */ budgetMin: 10|20|30|45; restDay: -1|0|1|2|3|4|5|6;
              goal: number /*0.8*/; examMode: boolean /*true*/; includeLower: boolean }
  // cards 키: '<l>-<idx>'(뜻) | '<l>-<idx>:r' | ':l' | ':w'
  triage: Record<Level, { q: number; checked: number; done: boolean }>
  streakTokens: number          // 쉼표 0~2
  bestE: number                 // 도장 최고치
}
```
이관(v2 → v3): `budgetMin = {10:10, 20:20, 30:30}[dailyNew] ?? 20`, `restDay = -1`, `goal = 0.8`, `examMode = true`, `includeLower = false`(기존 사용자 계획이 갑자기 늘지 않게), `triage = {}`, `streakTokens = 1`, `bestE = 0`. 기존 카드는 키와 내용 그대로 둔다. `restore`/`snapshot`은 `streakTokens`·`bestE`도 포함해야 한다. 백업 가져오기(`replaceState`)는 v2 파일이 들어와도 같은 이관을 타야 한다.

## 결정이 필요한 것

1. **대시보드 첫 지표를 "시험날 예상 기억 단어 수"로 바꿀지.** 추천: 바꾼다. 만난 단어 수는 시험 준비 상태를 말해 주지 않는다.
2. **준비도 대상에 하위 급수를 포함할지.** 추천: 신규 사용자는 포함(거르기로 빠르게 정리)하고, 기존 사용자는 기본 끔·설정에서 켜기. 시험은 하위 급수 어휘를 전제로 한다.
