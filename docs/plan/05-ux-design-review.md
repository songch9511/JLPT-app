## 결론과 추천

앱의 뼈대는 좋습니다. 카드 한 장에 집중하는 학습 화면, 쪽빛 하나로 정리된 강조색, 잠자다 차오르는 다루마는 의도대로 동작합니다. 문제는 세 가지입니다.

1. **학습 화면이 학습자를 정직하게 이끌지 못합니다.** 정답을 보기 전에도 `알아요`·`쉬워요`를 누를 수 있고, 프라이머리 색이 `알아요`에 있어서 확인 없이 `알아요`를 누르게 됩니다. 틀렸을 때는 화면이 거의 그대로라서 "틀렸다, 곧 다시 나온다"는 신호가 없습니다. 진행 막대는 오늘 이미 한 카드를 빼고 세서 30일째 사용자가 이어서 하면 0%에서 다시 시작합니다(`12-study-review-L`, 홈에서는 27%).
2. **홈이 게임 화면처럼 시끄럽고 길어졌습니다.** 첫 화면에 색이 7가지(쪽빛, 녹청, 황토, 감색 불꽃 6개, 금색 별, 주홍 다루마, 빨간 D-day)가 동시에 나오고, 매일 같은 퀘스트 3개가 세로 공간의 1/3을 차지합니다. 학습자가 첫 화면에서 알아야 할 것은 "오늘 몇 장, 몇 분, 시작 버튼" 하나입니다.
3. **기본기가 부족합니다.** 한국어 줄바꿈이 단어 중간에서 끊기고(`32-onboarding-320`의 "간/격이"), 글자 크기가 모두 px라서 iOS 글자 크기 설정이 반영되지 않으며, 대비가 WCAG AA에 못 미치는 조합이 9개 있습니다. 화면 낭독기로는 카드를 뒤집을 수 없습니다.

**추천 순서**: 1묶음(하루~이틀, 거의 CSS와 문구만)으로 줄바꿈, 대비, 결과 타일, 진행 막대, 문구를 고칩니다 → 2묶음에서 학습 화면 2단계 버튼(앞면: 정답 보기 / 뒷면: 3단계 평가)과 틀렸을 때 피드백을 넣습니다 → 3묶음에서 홈을 "오늘 카드 + 이번 주 + 시험 준비" 순으로 다시 짭니다(03 문서와 맞물림) → 4묶음은 접근성과 iOS 적합성입니다.

## 2. 화면별 진단

형식: **어디** — 문제와 학습자에게 미치는 영향 → 고칠 방법. `[심각도 · 공수]`
심각도: 방해(사용을 막음) / 저해(사용을 어렵게 함) / 다듬기.

### 2.1 온보딩 (`01-onboarding-L/D`, `32-onboarding-320`)

- **시작 버튼이 첫 화면 밖에 있습니다.** 390×844에서 버튼 위쪽 끝이 883px, 320×568에서는 두 화면 아래입니다. 설명 카드 3장을 다 읽어야 시작할 수 있습니다. → 설명 카드 3장을 한 줄짜리 목록(아이콘 없이 `b` 한 줄 + 설명 1줄)으로 줄이고, 다루마를 120→88px로 줄이고, 버튼을 `position: sticky; bottom: 0`에 배경 `var(--bg)`로 고정합니다. `[저해 · S]`
- **어느 급수를 골라야 할지 안내가 없습니다.** 처음 하는 사람은 N5/N1 차이를 모릅니다. → 급수 버튼 아래에 고른 급수의 한 줄 설명을 보여 줍니다(N5 "히라가나를 읽을 수 있으면 여기부터 · 718단어" 등). 문구는 03 문서의 커리큘럼 정의를 따릅니다. `[저해 · S]`
- **고른 조합이 현실적인지 알려 주지 않습니다.** 기본값(N5, 12월 6일, 하루 20개)은 시험일까지 718단어를 못 끝내는데(필요 32개/일), 홈에 가서야 알게 됩니다. → 시험일 칩 아래에 "이 속도면 시험 전까지 N5의 62%를 만나요" 한 줄을 실시간으로 보여 줍니다. 계산식은 03 문서와 공유합니다. `[다듬기 · S]`
- **이름이 "카사네 · 重ね"입니다.** 제품명은 "JLPT 루마" 방향입니다. → 개명 결정 후 `eyebrow`, `<title>`, `apple-mobile-web-app-title`, 백업 파일 이름, 알림 문구를 한 번에 바꿉니다. (결정 1)
- 온보딩 하루 새 단어는 10/20/30, 설정은 5/10/20/30/50입니다. → 둘 다 `5 · 10 · 20 · 30`에 "더 많이"는 설정에서만 열도록 통일합니다. `[다듬기 · S]`

### 2.2 홈 (`02-home-day1`, `10-home-day30`, `11-…-midway`, `13-…-backlog`, `14-…-finished`, `15-…-exampassed`)

정보 구조는 3장에서 따로 다룹니다. 여기서는 개별 문제만 씁니다.

- **HUD의 회색 불꽃.** 오늘 아직 안 했으면 30일 연속인데도 불꽃이 회색이라 끊긴 것처럼 보입니다(`10-home-day30-L`). → 회색 대신 윤곽선 불꽃(`fill: none`, `color: var(--flame)`)에 툴팁이 아닌 보이는 문구 "오늘 하면 31일"을 둡니다. `[저해 · S]`
- **할 일이 없는 날의 다루마.** 복습이 0장이면 공부를 안 했는데도 색이 가득 찬 채로 깨어 있습니다(`14-home-finished-L`). "공부해야 차오른다"는 규칙이 깨집니다. → 이때는 `mood="sleep"`, `fill=0`, 말풍선 "오늘은 쉬는 날이에요"로 둡니다. `[다듬기 · S]`
- **급수 완료 후 막다른 길.** `b.new === 0 && todo === 0`이면 버튼이 하나도 없습니다. → 히어로 버튼을 "N4 시작하기"(목표를 다음 급수로 바꾸고 학습 시작)로 바꾸고, 말풍선은 "N5 단어를 모두 만났어요. 다음은 N4!"로 둡니다. `[방해 · S]`
- **시험일이 지난 상태.** 칩이 `시험 종료`이고 안내 문장이 카드 아래쪽에 묻혀 있습니다(`15-home-exampassed-L`). → 칩을 "시험일 지남"으로 바꾸고 칩 자체를 설정 시험일로 가는 버튼(`a href="#/settings"`)으로 만듭니다. `[저해 · S]`
- **밀린 복습 430장.** 숫자만 크게 보이고 아무 안내가 없습니다(`13-home-backlog-L`). 밀린 사람이 가장 많이 그만두는 순간입니다. → 400장 이상이면 말풍선을 "밀린 복습이 많아요. 오늘은 100장만 해도 돼요"로 바꾸고, 히어로 버튼 아래에 고스트 버튼 "100장만 하기"를 둡니다. 큐 상한 로직은 03 문서 범위입니다. `[저해 · M]`
- **"지금 하루 20개 → 5개로 맞추기"** 링크는 누르면 설명 없이 설정이 바뀝니다. → 누른 뒤 같은 자리에 "하루 5개로 바꿨어요 · 되돌리기"를 4초 보여 줍니다. `[다듬기 · S]`
- **소요 시간이 없습니다.** "70장"은 감이 안 옵니다. → 히어로 숫자 줄에 "약 12분"(카드당 10초로 계산)을 붙입니다. `[다듬기 · S]`

### 2.3 학습 화면 (핵심 루프) (`03`~`06`, `12-study-review*`, `31-study-*`)

**지금 흐름**: 앞면에 3개 버튼이 이미 활성 → 카드를 탭하면 정답 공개 → 평가. `모르겠어요`만 공개 전 한 번 누르면 정답을 보여 주고 `확인했어요 · 다음` 하나로 바뀝니다.

- **(발견 1) 평가 버튼이 앞면부터 켜져 있습니다.** 버튼 3개가 모두 중립이고 위치로만 뜻을 구분하는데, 프라이머리가 `알아요`라서 "기본값 = 안다"로 읽힙니다. → 2단계로 나눕니다.
  - 앞면: `[모르겠어요]`(고스트, 1fr) `[정답 보기]`(프라이머리, 2fr). 카드 탭 = 정답 보기. `모르겠어요`는 지금처럼 정답을 보여 주고 "틀림" 상태로 갑니다.
  - 뒷면: `[모르겠어요 10분]` `[알아요 26일]`(프라이머리) `[쉬워요 2개월]`. 지금 배치 그대로입니다.
  - 키보드: Space/Enter = 정답 보기, 1/2/3 = 평가(지금의 ←/→/↑는 유지).
  - 앞면과 뒷면에서 버튼 높이와 위치를 같게(60px) 둬서 엄지가 움직이지 않게 합니다. `[방해 · M]`
- **(발견 2) 틀렸을 때 피드백이 없습니다.** → "틀림" 상태에서 ① 칩을 `다시 나와요 · 1분`(배경 `--again-soft`, 글자 `--again-deep`)으로 바꾸고 ② 카드 테두리 위쪽 3px을 `--again`으로 칠하고 ③ 읽기를 자동으로 한 번 들려줍니다(`autoSpeak`와 무관). 빨간 화면 전체 색칠이나 흔들기는 하지 않습니다(차분함 유지). `[저해 · S]`
- **답한 뒤 피드백.** 지금은 XP 숫자 옆에 `+10`만 뜹니다. "언제 다시 보는지"가 학습자에게 더 의미 있습니다. → 다음 카드가 들어올 때 진행 막대 오른쪽에 `26일 뒤` 같은 짧은 문구를 0.9초 보여 주고 사라지게 합니다(`aria-live="polite"`). XP 팝업은 퀘스트 보상이 있을 때만 남깁니다. `[다듬기 · S]`
- **진행 막대가 오늘 진행과 다릅니다.** 분모가 이번 세션에서 답한 수라서 이어서 하면 0부터 시작하고, 0일 때 `min-width: 18px`가 원형 손잡이처럼 보입니다(`03-study-front-L`). 색도 혼자 녹청입니다. → 홈과 같은 식 `오늘 c / (오늘 c + 남은 장수)`를 쓰고, `min-width` 제거, 색 `--accent`, 높이 18→8px. 막대 오른쪽에 `남은 46장`을 둡니다. `[저해 · S]`
- **위쪽 색깔 숫자 줄(`복습 40 외우는 중 10 새 단어 14`)과 카드 칩이 같은 말을 두 번 합니다.** 3색 숫자는 학습 중 집중을 깹니다. → 숫자 줄을 지우고 `남은 N장`만 남깁니다. 카드 칩은 유지하되 `새 단어`일 때만 보이게 합니다(복습 카드에서 "복습" 칩은 정보가 없음). `[다듬기 · S]`
- **320px에서 `모르겠어요`가 두 줄로 깨집니다**(`31-study-320`). → `.answer-bar .btn`에 `white-space: nowrap; font-size: 15px`, 320px 이하에서 `grid-template-columns: 1fr 1.15fr 1fr; gap: 6px`. `[저해 · S]`
- **"잠깐 쉬어 가요" 화면이 멈춰 있습니다.** 외우는 중 카드가 몇 분 뒤 돌아와도 화면이 다시 계산되지 않아서 나갔다 와야 합니다(`useMemo`가 시간에 반응하지 않음). → 다음 카드 시각을 문구로 보여 주고("3분 뒤에 4장이 돌아와요"), 그 시각에 맞춰 `setTimeout`으로 다시 계산합니다. `[저해 · S]`
- **AI 오류가 카드 안에서 빨간 두 줄로 나옵니다**(`06-study-ai-nokey-L`). 학습 중 기술 용어(Anthropic API 키)가 나옵니다. → 키가 없으면 버튼 자체를 숨기고, 설명 링크 대신 "AI 설명은 설정에서 켤 수 있어요" 회색 한 줄. AI 구조 자체는 01·07 문서를 따릅니다. `[다듬기 · S]`
- **엄지 범위**: 평가 버튼은 아래쪽이라 좋습니다. 되돌리기는 오른쪽 위(엄지에서 가장 먼 곳)입니다. 실수 직후 바로 쓰는 버튼이므로 → 답한 뒤 4초간 아래 버튼 줄 위에 `되돌리기` 작은 고스트 칩을 띄우고, 위쪽 아이콘은 유지합니다. `[다듬기 · M]`
- **카드 등장 애니메이션**(`translateX(24px) rotate(1.5deg)`, 튀는 곡선)은 하루 100번 보면 피곤합니다. → `opacity 0→1, translateY(8px→0)`, `160ms`, `ease-out`. `[다듬기 · S]`

### 2.4 완료 화면 (`07-done-L/D`, `07-done-settled-*`)

- **결과 타일 대비 미달(발견 5)과 게임 느낌.** 금·감·녹 3색 테두리 타일 + 4색 색종이는 앱에서 가장 "게임 UI"다운 부분입니다. → 타일을 `.card` 스타일(배경 `--surface`, 1px `--line`)로 바꾸고 머리글은 `--muted` 12px, 숫자만 `--text` 24px. 색종이는 18개 4색 → 다루마 응원 + 주홍 도장("済") 한 번 찍히는 효과(0.4초)로 바꿉니다. (결정 3) `[저해 · S]`
- **`계속하기`가 홈으로 갑니다.** "더 공부한다"로 읽힙니다. → `홈으로`. 고스트 `새 단어 10개 더 하기`는 유지. `[저해 · S]`

### 2.5 급수 화면 (`20-level-L/D`, `22-level-empty-*`)

## 4. 시각 디자인

### 4.1 글꼴

- **본문 기본 굵기가 600, 제목은 800**입니다. 거의 모든 글자가 굵어서 위계가 무게가 아니라 크기에만 의존하고, 전체가 "게임 UI"처럼 무겁게 보입니다. → 본문 500(대부분 한국어 글꼴에서 Medium), 강조 700, 800은 쓰지 않습니다. 숫자 강조만 700.
- **글자 크기가 15가지**입니다(11·12·13·14·15·16·17·18·19·21·22·24·26·30·44px + clamp 2개). → 5장의 6단계로 줄입니다.
- **둥근 UI 글꼴은 사실상 라틴 숫자에만 적용됩니다.** `ui-rounded`(SF Pro Rounded)는 Safari 전용이고 한글 글리프가 없어서 한글은 Apple SD Gothic Neo로 떨어집니다. 결과적으로 "둥근 숫자 + 각진 한글"이 섞입니다. → 숫자 전용 클래스(`.num`)에만 `ui-rounded`를 쓰고 본문은 `-apple-system, 'Apple SD Gothic Neo', Pretendard, 'Noto Sans KR'`. 판단은 결정 4.
- **표제어 명조**: iOS(히라기노 명조 W6)에서는 의도대로 나오지만, 안드로이드·윈도에는 명조가 없어 고딕으로 떨어집니다(이번 캡처가 그 예). 명조가 이 앱의 "일본 전통" 인상을 가장 많이 만들어 내므로 → iOS 앱에서는 그대로, 웹 PWA는 Noto Serif JP 600을 Google Fonts `unicode-range` 분할로 부릅니다(필요한 조각만 받음). 굵기는 800 → 600(W6에 맞춤, 가짜 굵기 방지).
- **줄바꿈**(발견 3): `body { word-break: keep-all; overflow-wrap: anywhere; }` 한 줄로 고쳐집니다. 일본어 표제어(`[lang='ja']`)는 `word-break: normal` 유지. `[저해 · S]`
- **글자 크기 설정 무시**: 모든 크기가 px라 iOS "더 큰 텍스트"가 반영되지 않습니다(`34-study-textzoom`이 변화 없음). → 크기를 rem으로 바꾸고, iOS에서는 `html { font: -apple-system-body; }`로 시스템 크기를 받은 뒤 기준을 17px→16px로 맞춥니다. 버튼 높이는 `min-height`라 커지는 글자를 견딥니다. `[저해 · M]`

색 이름과 히어로의 세이가이하 무늬, 명조 표제어는 의도를 잘 살립니다. 하지만 히어로 밖에서는 둥근 굵은 글씨, 3D 버튼, 금·감·녹 원판이 "일반 게임 학습 앱"의 인상을 만듭니다. 덜어내는 쪽으로 전통 느낌을 키우기를 추천합니다.
- 여정 도장(이미 "도장"이라 부름)을 녹색 체크 원판 대신 **주홍 인주 도장**으로: 지름 44px 원, 1.5px `--again` 테두리 + 안쪽 글자 `済`(명조 18px, `--again`), 살짝 회전(-8°). 미완료는 점선 원. `[다듬기 · M]`

## 8. iOS 앱으로 갈 때

앱 포장 방식(WKWebView 래퍼 등)은 06 문서를 따릅니다. 화면 쪽에서 준비할 것:

- **안전 영역**: `env(safe-area-inset-*)`가 페이지·학습·탭바·시트에 이미 들어가 있습니다. 가로 모드 좌우(`inset-left/right`)는 빠져 있음 → `.page`, `.answer-bar` 좌우 패딩에 `max(16px, env(safe-area-inset-left))`. `[다듬기 · S]`
- **글자 크기(Dynamic Type)**: 4.1. 심사에서 직접 거절 사유는 아니지만 접근성 평가와 리뷰에 영향. `[저해 · M]`
- **햅틱**: 웹에는 없습니다(iOS Safari는 Vibration API 미지원). 앱에서는 정답 공개 시 `selection`, `알아요/쉬워요` `light`, `모르겠어요` `soft`, 오늘 완료 시 `success` 한 번. 게임처럼 매번 강하게 울리지 않게 합니다. `[다듬기 · S, 앱 단계]`
- **웹 같아 보이는 것**: 체크박스(→스위치), `confirm()/alert()`(→네이티브 경고창), 날짜 입력(→네이티브 날짜 선택), 해시 주소(앱에서는 보이지 않으므로 무관), 버튼 길게 누르면 글자 선택됨(→ 버튼·탭바에 `user-select: none; -webkit-touch-callout: none`), 당겨서 새로고침/튕김(이미 `overscroll-behavior-y: none`).
- **제스처**: 급수 화면에서 왼쪽 가장자리 밀어 뒤로 가기(웹뷰 `allowsBackForwardNavigationGestures`), 시트 끌어 닫기(2.6), 학습 카드 좌우 밀기는 넣지 않기를 추천(실수로 평가가 들어갈 위험).
- **상태 표시줄**: `theme-color`가 테마에 따라 바뀌는 처리는 좋습니다. 학습 화면에서도 같은 배경이라 문제 없음.
- **아이패드**: 520px 가운데 기둥이 1024px에서 양옆이 비어 보입니다(`30-home-tablet`). 1차는 그대로 두고, 아이패드를 지원 기기로 낼 경우 홈을 2열(왼쪽 오늘·이번 주, 오른쪽 시험 준비·기록)로. 06 문서의 지원 기기 결정에 따름.

### 가볍게 하기 (2026-11-14)

소유자 결정: 테마(토큰)는 그대로, Astryx 컴포넌트는 실제로 나아진 것(확인·알림 대화상자, 아래 시트)만 남기고 나머지는 가볍게 직접 만든다.
- **잰 것**: React만 66KB, 대화상자·시트·스위치 + 테마 공급자 246KB(gzip JS). 여기에 버튼·카드·세그먼트·칩·검색칸·진행 막대·배지·배너·빈 상태·스켈레톤을 다 더해도 +26KB뿐이라, 그것들만 바꾸면 거의 줄지 않습니다. 무게의 대부분은 어떤 Astryx 컴포넌트든 따라오는 공통 기반(약 150KB)이고, 스위치 하나가 98KB를 끌고 옵니다.
- **그래서**: 대화상자·시트는 Astryx 그대로 따로 불러오는 묶음(`src/components/overlays.tsx`)으로 옮기고, 스위치를 포함한 나머지 컨트롤은 `src/components/ui.tsx`에서 직접 만듦(같은 API, 같은 모양). 테마 공급자(`<Theme>`)도 빼고 테마 모드·Dynamic Type은 `src/themeRoot.ts`가 맡음. Astryx CSS는 기본 토큰 중 읽는 것만(0.8KB)과 대화상자·시트가 쓰는 규칙만(14KB, 따로 불러옴) 남김.
- **결과**(gzip): 처음 불러오는 JS 313→105.7KB(이전 102.3), CSS 51.2→10.7KB(+ 따로 14KB), 홈까지 시간은 Astryx 이전과 같은 수준. 자세한 수치는 `docs/design-system.md` 9장.
- **그대로인 것**: 앱 안 대화상자(안전한 선택에 초점, Esc로 닫고 연 버튼으로 초점 복귀, 초점 가둠), 시트(손잡이, 아래로 밀어 닫기), 진짜 스위치, 단계 필터 줄바꿈 칩, 단계 글자 태그, 온보딩 시작 버튼 고정, 부드러운 주홍 지우기 버튼, 44px 누름 영역, 대비 44쌍, 동작 줄이기, 시스템·라이트·다크.
- **함께 고친 것**: 아이콘 버튼의 Lucide 아이콘이 Astryx에서 16px로 줄어 있던 것을 원래 크기(22px)로, 좁은 화면에서 `읽기` 배지가 `읽`으로 잘리던 것.

### 온보딩 없애기 · 루마의 안내 (2026-11-14)

소유자 피드백(실기기): 온보딩이 설명 카드 3장 + 급수·하루 새 단어·시험일 선택이 이어지는 긴 양식이라 스크롤해야 했음. "온보딩을 없애고 대시보드 안에서 루마가 설명해 주는 게 좋겠다", 듀오링고 참고. 방식(마스코트가 이끌고, 한 화면에 질문 하나, 바로 첫 학습, 설명은 미리가 아니라 그 순간에)만 참고하고 모양은 ruma 디자인 시스템 그대로입니다. 자세한 문구·규칙은 [`docs/design-system.md`](../design-system.md) 3장 "첫 화면 · 루마의 안내".
- **온보딩 화면 삭제**(`Onboarding.tsx`, `.onboard`·`.how` 스타일). 새 사용자는 바로 홈.
- **첫 화면(launch)**: `index.html`에 바탕색 전체 + 가운데 루마 + 아래 "JLPT 루마". 스크립트 전에 칠해지고 앱이 그려지면 바로 페이드(최소 시간 없음, 동작 줄이기면 즉시). iOS 시작 이미지와 바탕색 에셋도 같은 모양으로.
- **홈에서 루마가 묻기**: 급수(N5~N1) → 시험일(다음 3회 + 아직 몰라요) → 첫 학습 시작. 답할 때마다 저장, 준비도·계획 카드는 답이 들어오는 만큼 채워짐(그 전엔 숫자 없이 자리만). 하루 새 단어는 묻지 않고 기본 20(설정·계획 카드의 "바꾸기"에서 바꿈). 아래 급수 함께는 기본 켬이고 말풍선이 알려 줌("쉬운 N5·N4 단어도 함께 나와요").
- **"아직 몰라요"**: 앱은 늘 시험일이 있어야 계획을 세우므로, 모든 새 상태의 기본값(다음 JLPT 날짜)을 그대로 두고 그렇다고 말함("시험일은 일단 12월 6일로 둘게요. 설정에서 바꿀 수 있어요.").
- **설명은 그 순간에 한 번**: 처음 공부한 뒤 간격 반복, 첫 읽기 카드, 준비도 판정이 처음 나올 때(합격 확률이 아니라는 말 포함). 눈 뜨는 이야기는 기존 말풍선이 이미 그 순간에 함. 셋 다 닫을 수 있고 화면을 막지 않으며 다시 나오지 않음. 설정에 "루마의 안내 다시 보기".
- **기존 사용자 보호**: 안내 진행은 상태의 새 선택 필드 `guide`에만 있고, 이 버전으로 처음 시작한 사람만 가짐. 이전 사용자·그들의 백업(`onboarded: true`, `guide` 없음)은 질문도 팁도 보지 않음. 상태 버전은 그대로(v4).
- **2.1의 남은 항목**: 급수 안내는 한 줄("처음이라면 N5부터 시작해요")로, 페이스 미리보기는 하지 않음(첫 학습 단계에서 계획 카드의 "하루 새 단어 n개면 목표에 닿아요 · 바꾸기"가 그 역할).

### 홈 "루마의 하늘" · 문구 규칙 (2026-11-14)

소유자가 홈 목업(A·B·C, 다시 C1·C2·C3, 문구 3·4차)을 보고 **C3 "루마의 하늘"**을 골랐고, 문구에 대해 "설명하는 문장, 추임새, 부사, 느낌표를 없앤다"는 규칙을 정했습니다. 구조·토큰·도장·문구 규칙은 [`docs/design-system.md`](../design-system.md) 3장 "홈 '루마의 하늘'"과 "문구".
- **구조**: 마스코트 카드·말풍선·계획 카드·만난 단어 카드·보조 링크 → 위쪽 하늘(머리줄, 큰 루마, 루마의 한 줄, 日月火水木金土 도장 주간, 아래 青海波) + 그 위로 올라오는 시트(큰 숫자 하나, 작은 시간·개수·"밀린 n" 태그, 56px 알약 프라이머리 하나, 조용한 글자 버튼, 만난 단어 줄 → 기록). 하늘색이 루마의 상태(잠듦·한쪽 눈·두 눈·쉬는 날)를 따르고 바뀔 때 천천히 넘어감(동작 줄이기면 바로). 홈에서는 탭바가 시트색.
- **목업에 없던 상태**: 익히는 중 카드를 기다릴 때("n분 뒤"), 쉬는 날("오늘은 쉬어요", 남은 새 단어가 있으면 "새 단어 10개 더"가 프라이머리), 급수를 다 만남("다음은 N4예요" + "N4 시작하기"), 오늘 끝인데 밀린 게 남음(태그 + "50장 더"), 첫 학습(새벽 하늘, "깨워 줄래요?", 시작하기 + "급수 다시 고르기"), 간격 반복 팁(루마의 말 자리, 두 문장 + "알겠어요").
- **뺀 것**: 퀘스트 표시(퀘스트·XP는 그대로), "그중 장기 기억", 약한 단어·기록 줄(탭으로), "(읽기만 n)", 밀린 복습 문단과 "n일이면 따라잡아요", 보이는 "오늘 하면 n일"(낭독 이름에는 남음). 백업 권유는 설정 › 데이터로 옮기고 설정 탭에 작은 점.
- **동작은 그대로**: 큐, 밀린 복습 정책, 개수, 모든 버튼의 동작과 "더"의 되돌리기. `tests/unit/counts-agree.test.ts`는 고치지 않고 통과.
- **색**: 하늘 4가지와 青海波 선 4가지, 하늘 위 보조 글자, 도장색을 테마 토큰으로(라이트·다크). 하늘 위 글자는 모두 5:1 이상(목업은 도장 4.5, 보조 글자 4.8). 柿 불꽃을 조금 짙게(하늘 위 3:1). 단위 테스트 40쌍 추가.
- **짧은 화면·큰 글자**: 높이 700 이하와 iOS AX 글자 크기에서 하늘이 한 줄로 접힘. 320×568에서 모든 상태가 스크롤 없이 들어감(e2e `home.spec.ts`), AX3·AX5에서도 시작 버튼이 첫 화면 안.
