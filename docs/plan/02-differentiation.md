# 02. 앱 차별화 — 경쟁 분석, 포지셔닝, 기능 우선순위

작성 2026-11-13 · 외부 사실 확인일은 모두 2026-11-13 (따로 적은 곳 제외)

> **2026-11-14 철회(소유자 결정)**: 기둥 2 "시험일 기준 정직한 준비도"와 F1 "시험날 기억 예측"은 철회했고 앱에서 없앴습니다. 소유자: "시험날 기억할 단어라든가 시험일에 대한 정보는 구지 필요없으니까 앱의 전역에서 없애줘. 그와 관련된 UX flow도 없애줘." 차별화는 기둥 1(한자어 지름길)과 F2~F4로 갑니다. 아래 본문은 당시 분석 기록으로 남깁니다(지운 것 목록은 03 끝 "구현 현황 (2026-11-14): 시험일과 준비도 제거").

## 0. 결론

**한 문장 포지셔닝**: "한국어를 이미 아는 사람을 위한 JLPT 단어장. 한자어로 이미 아는 단어는 빨리 지나가고, 시험날 실제로 기억하고 있을 단어 수를 정직하게 보여 준다."

- **왜 이 앱인가에 대한 답은 두 개로 좁힙니다.** (1) **한자어 지름길**: 한국어 화자에게 N3~N1 단어의 40% 안팎은 뜻이 거의 공짜입니다(아래 3.1의 자체 추정). 지금 앱과 경쟁 앱 모두 이 단어들을 다른 단어와 똑같이 취급해 시간을 씁니다. (2) **시험일 기준 준비도**: FSRS 기억 모델로 "시험날 기억할 단어 수"를 계산해 보여 줄 수 있는 앱은, 확인한 한국 스토어 앱 중에는 없습니다.
- **AI 설명**과 **차분한 습관 루프**는 차별화 기둥이 아니라 기둥을 받치는 수단이나 설계 원칙으로 둡니다. AI 설명은 이미 흔해졌고 API 키를 직접 넣는 지금 구조로는 제품에서 쓸 수 없으며, '차분함'은 광고할 수 있는 이유가 되지 못합니다(3.3).
- **다음 4주에 만들 것 (우선순위 순)**: ① 시험날 기억 예측(준비도) ② 단어별 한자어 분류 데이터(동형동의 / 거짓 친구 / 고유어 / 외래어 + 한국 한자음) ③ 한자어 빠른 통과 모드(뜻 대신 **읽기**를 확인) ④ 한·일 한자음 대응 힌트. 뜻 검수 신고 버튼은 차별화가 아닌 기본 요건이라 같은 기간에 함께 처리합니다.
- **만들지 않을 것**: 문법·독해·청해 코스, 모의고사, 랭킹·리그, 하트 같은 벌칙, 사용자 덱 편집기, AI 회화. (5절)
- **이름**: 브랜드에 "JLPT"를 넣지 말고, 스토어 표시명의 설명 부분에서만 사실 그대로 씁니다(예: "루마 — JLPT 일본어 단어"). "루마"는 국내에서 자동차 썬팅 브랜드(LLumar)로 검색 결과가 덮여 있고, 해외에는 Luma AI·Luma Speak(AI 회화 앱) 등이 있어 검색성이 약합니다. 학습 앱 분야에서 직접 충돌하는 상표는 찾지 못했지만 KIPRIS 조회는 하지 못했습니다(6절).
- **놀라운 점**: (a) 12월 JLPT가 **2026-12-06**, 즉 23일 뒤입니다. 지금 들어오는 사용자는 벼락치기 중이고, 실질적인 출시 목표는 2027년 7월 시험 접수 시기입니다. (b) 국내 JLPT 단어 앱 가운데 한국어–일본어 한자어 관계를 학습 방식에 반영한 앱은 찾지 못했습니다. AI 팁 프롬프트(`src/ai-client.ts`)에 "한국 한자어와의 연결"이 이미 들어 있으니, 이것을 데이터로 굳히면 됩니다. (c) 회독JLPT(AD)는 '안다/다시 공부' 두 가지 분류만으로 평점 4.7(559개)을 받습니다. 단순함이 경쟁력이라는 뜻이므로, 새 기능 때문에 학습 화면이 복잡해지면 안 됩니다.

### 1.3 경쟁 구도에서 읽히는 것

1. **국내 JLPT 단어 앱 시장은 작은 개발사의 단어장이 많고 서로 비슷합니다.** 레벨별 목록, 플래시카드, 음성, 일부 망각 곡선이 공통입니다. "더 많은 단어, 더 좋은 음성"으로는 회독JLPT 유료판(₩22,000, 현지 녹음)이나 그림 단어장과 차이를 만들 수 없습니다.
2. **잘 만든 해외 앱(WaniKani, Bunpro, Renshuu, Anki)은 모두 영어 화자를 전제로 합니다.** WaniKani의 핵심 가치인 한자 뜻 니모닉은 한국어 화자에게 상당 부분 필요 없습니다. 한국어 화자가 이미 가진 것을 활용하는 앱은 비어 있는 자리입니다.
3. **"시험까지 남은 날 + 기억 모델"을 함께 쓰는 앱은 찾지 못했습니다.** 하루10단어는 분량을 고정하고, 회독은 사용자가 회독 횟수를 관리하며, Anki는 시험일 개념이 없습니다. JLPT Plus가 가장 가깝지만 목록에는 준비도 예측이 없습니다(앱 안에서 확인하지는 못함 — 미확인).
4. **종합 대비(문법·독해·청해·모의고사)는 "오늘부터 일본어" 같은 앱과 교재·인강이 이미 차지했습니다.** 이 싸움에 들어가면 1인 개발로는 콘텐츠 양에서 집니다.
5. **말해보카가 일본어로 넘어오는 것이 가장 큰 잠재 위협입니다.** 마케팅과 게임성에서는 이길 수 없으니, 그들이 쉽게 따라 하지 못하는 쪽(시험 특화, 한자어 데이터, 정직한 예측)으로 가야 합니다.

## 2. 현재 앱의 위치 — 정직한 진단

### 2.1 이미 차별점이 되는 것

| 요소 | 코드 근거 | 평가 |
| --- | --- | --- |
| FSRS 스케줄링 + 답 버튼에 다음 간격 표시("알아요 4일") | `src/srs.ts` `previewIntervals`, `src/screens/Study.tsx` 답 버튼의 `<small>` | 회독식 이분법이나 고정 간격보다 확실히 낫고 투명합니다. 다만 Anki도 FSRS를 쓰므로 알고리즘만으로는 차별점이 아닙니다. **"그래서 시험날 몇 개를 기억하나"로 번역해야** 가치가 생깁니다. |
| 시험일 연동 목표 | `Home.tsx` `needPerDay = ceil(b.new / dday)`, "하루 N개로 맞추기" 버튼 | 좋은 출발점입니다. 하지만 **"전부 만나기"만 계산하고 "기억하기"는 계산하지 않습니다.** 하루 34개씩 새 단어를 보면 다 만나기는 하지만 복습이 폭증해 시험날 기억률은 낮아집니다. 지금 문구는 낙관적이라 정직하지 않습니다. |
| 다루마 마스코트(잠듦 → 색이 차오름 → 환호) | `Daruma.tsx`, `Home.tsx`의 `progress` | 감정적인 호소력이 있고 오늘 분량에 묶여 있어 의미가 분명합니다. 브랜드 자산으로 좋지만 다운로드 이유는 되지 못합니다. |
| 한국어 화자에게 맞춘 AI 설명 | `src/ai-client.ts`: 한국 한자음 풀이, "한국 한자어와의 연결" 팁 | 방향이 옳고 기둥 1의 씨앗입니다. 하지만 사용자가 직접 API 키를 넣는 구조라 실제 사용자 대부분은 쓸 수 없습니다(01 문서의 AI 원가 항목 참조). |
| 정직함을 해치지 않는 XP(답과 무관하게 카드당 10) | `srs.ts` `XP_PER_CARD` | 작지만 좋은 원칙입니다. "모르겠어요"를 눌러도 손해가 없습니다. |

### 2.2 기본 요건일 뿐이거나 빠진 것

- **예문·품사·원어민 음성 없음**: 경쟁 유료 앱의 기본입니다(회독 유료판, 그림 단어장). 무료일 때는 괜찮지만 유료화하면 빠진 것이 바로 보입니다.
- **단어만 다룸**: 문법·한자 쓰기·독해·청해가 없습니다. 5절에서 의도된 범위로 정리합니다.
- **계정·동기화 없음**: 기기를 바꾸면 기록이 사라집니다. 결제가 들어가면 필수입니다(07 문서).
- **한국어 뜻 전수 검수 안 됨**: 표본에서 `天皇=일왕`(표기 선택의 문제), `余計=여분`(대표 뜻이 아님)처럼 대표 뜻이 어긋난 항목이 보입니다. 단어장에서 뜻 오류는 신뢰를 바로 깎습니다. 차별화 이전의 문제입니다.
- **단어 순서와 분류 없음**: `nextNewIds`가 데이터 파일 순서대로 새 단어를 냅니다. 품사·빈도·한자어 여부 같은 정보가 없어서 어떤 단어를 먼저 보여 줄지 똑똑하게 고를 수 없습니다. **기둥 1에 필요한 데이터 작업이 곧 이 문제의 해결책이기도 합니다.**
- **측정 수단 없음**: 분석 도구가 없어 아래 기능들의 효과를 잴 수 없습니다. 최소한의 이벤트 수집이 필요합니다(07 문서와 협의).

## 3. 포지셔닝과 차별화 기둥

### 3.1 근거 데이터: 한자어가 얼마나 되나 (자체 추정)

`public/data/n*.json`에서 (a) 2글자 이상이 모두 한자인 단어와 (b) 그중 첫 번째 한국어 뜻이 같은 글자 수의 한글 한 단어인 경우(한자어 직역 가능성이 높음)를 세었습니다.

| 급수 | 단어 수 | (a) 한자만으로 된 단어 | (b) 뜻이 한자어 직역형 |
| --- | --- | --- | --- |
| N5 | 718 | 192 (27%) | 132 (18%) |
| N4 | 668 | 233 (35%) | 196 (29%) |
| N3 | 2,140 | 975 (46%) | 893 (42%) |
| N2 | 1,905 | 913 (48%) | 777 (41%) |
| N1 | 2,699 | 1,559 (58%) | 1,368 (51%) |

- (b)에서 무작위로 41개를 뽑아 보니 약 80%가 실제 동형동의 한자어였습니다(調整=조정, 清掃=청소, 演劇=연극…). 나머지는 引算=뺄셈, 献立=메뉴, 余計=여분처럼 직역이 아닌 경우였습니다. **보수적으로 잡아 N3~N1 단어의 약 1/3~2/5가 "뜻은 한국어로 바로 추론 가능"**합니다. 정확한 값은 기능 F2의 분류 데이터로 다시 확정해야 합니다.
- **중요한 단서**: JLPT 문자·어휘 영역은 **읽기(漢字読み)와 표기**를 묻습니다. 図書館의 뜻은 공짜지만 "としょかん"이라는 읽기는 공짜가 아닙니다. 그러니 한자어 지름길은 "건너뛰기"가 아니라 **"뜻 확인은 건너뛰고 읽기 확인으로 바꾸기"**여야 합니다. 한국 한자음과 일본 음독 사이에는 경향성 있는 대응이 있습니다(ㄴ·ㅁ 받침→ン, ㅇ 받침→ウ/イ, ㄹ 받침→ツ/チ, ㄱ 받침→ク/キ). 완벽한 규칙은 아니지만 학습 힌트로는 충분합니다([하소정·이경철 등 대응 연구 요약](https://wikidocs.net/188141), [한일 한자음 대응 논문](https://scholar.korea.ac.kr/handle/2021.sw.korea/134176?mode=full)).
- 거짓 친구(동형이의어)도 확실히 있습니다. 한·일 기본 어휘에서 같은 형태의 한자어 319개를 뽑아 의미 차이를 분석한 연구가 있고([교보 스콜라](https://scholar.kyobobook.co.kr/article/detail/4010028498893)), 勉強(공부 ≠ 면강), 工夫(궁리, 연구), 大丈夫, 留守, 手紙 같은 단어는 한국어 화자가 **틀리게 확신하는** 단어라 오히려 시간을 더 써야 합니다.

### 3.2 포지셔닝 문장

> **JLPT를 준비하는 한국인을 위해**, 루마는 **한국어로 이미 아는 한자어는 빨리 지나가고 시간을 헷갈리는 단어에 쓰게 해 주며, 시험날 실제로 기억하고 있을 단어 수를 보여 주는 단어 앱**입니다. **회독식 단어장이나 Anki와 달리** 언제 무엇을 다시 볼지 앱이 정하고, 그 결과를 시험일 기준으로 정직하게 말해 줍니다.

### 3.3 후보 기둥 평가

| 후보 | 판정 | 이유 |
| --- | --- | --- |
| **A. 한자어 지름길** (동형동의는 빨리, 거짓 친구와 고유어에 집중) | **채택 — 기둥 1** | 한국어 화자만 얻을 수 있는 이점이고(영어권 앱은 구조적으로 못 함), 데이터로 증명할 수 있으며(3.1), 효과를 숫자로 말할 수 있습니다("N2 단어 1,905개 중 약 700개는 읽기만 확인"). 국내 앱 가운데 이것을 학습 방식에 반영한 사례는 찾지 못했습니다. 위험: 읽기를 소홀히 하게 만들 수 있음 → 읽기 확인으로 바꾸는 설계로 해결합니다. |
| **B. 시험일 역산 + 정직한 준비도** ("붙을 수 있을까?") | **채택 — 기둥 2** (2026-11-14 소유자 결정으로 철회) | 시험이라는 마감이 있는 학습자에게 가장 큰 불안을 직접 다룹니다. FSRS가 이미 단어별 기억 확률을 계산할 수 있어서 추가 데이터 없이 만들 수 있습니다. 조건: **합격 확률은 말하지 않습니다.** 단어는 시험의 일부(언어 지식 영역)일 뿐이라 "합격 예측"은 거짓말이 됩니다. "시험날 기억할 N2 단어 수 추정"과 "지금 속도로 가면 / 하루 몇 개로 바꾸면"까지만 말합니다. |
| **C. 한국어 화자 맞춤 AI 설명** | **기둥이 아닌 수단으로 격하** | AI 설명은 이제 어느 앱이나 붙일 수 있고, 사용자 입장에서 "AI가 있다"는 다운로드 이유가 되지 못합니다. 가치는 A의 내용(한자음 대응, 거짓 친구 차이 설명)에서 나옵니다. 그래서 **8,130단어 설명을 미리 생성하고 검수해 데이터로 배포**하는 것이 맞습니다(F9). 사용자별 실시간 호출 비용과 키 문제가 함께 사라집니다. |
| **D. 차분하고 잔소리 없는 습관 루프** | **기둥에서 제외, 설계 원칙으로 유지** | 광고할 수 있는 이유가 아니고, 이미 XP·연속 학습·퀘스트가 있어서 "게임 없는 앱"이라고 주장할 수도 없습니다. 대신 원칙으로 지킵니다: 하트·벌칙 없음, 놓친 날을 탓하는 알림 없음, 알림은 하루 한 번 이하, 복습이 밀리면 "오늘은 이만큼만" 상한을 둠. |
| **E. (추가 검토) 시험 형식 문제 연습** | **나중으로(F11)** | 단어 앱 안에서 문자·어휘 영역 문제 형식(읽기 고르기, 표기, 문맥 규정, 유의어)을 연습하는 것은 플래시카드와의 차이를 만들지만, 문제 생성·검수 부담이 커서 기둥 1·2가 자리 잡은 뒤에 합니다. |

**최종 기둥 (2개 + 원칙 1개)**
1. **한자어 지름길** — 한국어로 아는 것은 빨리, 헷갈리는 것에 시간을.
2. **시험일 기준 정직한 준비도** — "시험날 기억할 단어 수"와 그것을 바꾸는 하루 분량.
3. (원칙) **차분한 매일** — 다루마가 차오르는 하루 한 번의 루프, 벌칙 없음.

기둥을 세 개 이상으로 늘리지 않는 이유: 1인 개발 규모에서 마케팅 메시지와 개발 역량을 둘에 집중해야 각각이 경쟁 앱보다 확실히 나아집니다.

## 4. 기능 우선순위

크기: S = 1~3일, M = 1~2주, L = 3주 이상 (현재 코드 기준, 1인).
측정은 분석 도구가 없으므로 F0을 먼저 둡니다. 대시보드 배치와 화면 명세는 03 문서가 담당하고, 여기서는 무엇을 왜 만드는지만 정합니다.

### 4.1 다음 4주 (2026-11-16 ~ 12-13)

12월 6일 시험 직전이라 지금 사용자에게는 F1이 가장 쓸모 있고, F2~F4는 2027년 7월 시험 시즌을 위한 준비입니다.

**F0. 최소 측정 (S)** — 차별화 기능은 아니지만 아래 기능들의 효과를 재기 위한 전제입니다.
- 내용: 익명 이벤트 몇 개(세션 시작, 카드 답, 오늘 분량 완료, 준비도 카드 열람, 빠른 통과 사용). 개인정보 최소화.
- 의존성: 도구 선택과 개인정보 처리 → 07 문서.
- 측정: 이벤트가 하루 단위로 집계되면 완료.

**F1. 시험날 기억 예측 ("시험날 몇 개나 기억할까") (S~M)** — *2026-11-14 철회, 앱에서 제거*
- 내용: 목표 급수의 모든 카드에 대해 FSRS 망각 곡선으로 **시험일 시점의 기억 확률**을 계산해 더합니다(`ts-fsrs`의 retrievability 계산 사용). 아직 안 본 단어는 현재 하루 새 단어 수로 시험일까지 만날 단어를 추정하고, 신규 카드의 평균 기억률을 적용합니다. 결과는 "지금 속도: 시험날 약 1,240 / 1,905개 기억" + "하루 새 단어 25개 → 약 1,450개, 대신 하루 복습 약 90장"처럼 **두세 가지 시나리오**로 보여 줍니다. 지금의 `needPerDay` 문구("전부 만나려면 하루 N개")를 대체합니다.
- 왜 차별화인가: 기둥 2의 핵심입니다. 회독·하루10단어·Anki 모두 시험일 기준 숫자가 없습니다. "다 만나기"가 아니라 "기억하기"를 말하는 것이 정직함입니다.
- 의존성: 데이터·백엔드·AI 없음. 시나리오별 복습 부하 추정은 간단한 시뮬레이션(평균 간격 기반)으로 충분합니다.
- 측정: 준비도 카드를 본 사용자 중 하루 분량을 바꾼 비율, 바꾼 뒤 7일 동안 오늘 분량 완료율. 장기적으로는 시험 뒤 자가 보고 결과와 비교(F12).

**F2. 단어별 한자어 분류 데이터 (M)**
- 내용: `scripts/build-data.mjs`에 단계를 추가해 단어마다 `kind`(동형동의 한자어 / 거짓 친구 / 고유어(和語) / 외래어 / 혼합)와 한국 한자음(예: 図書館 → 도서관)을 붙입니다. 한국 한자음은 Unicode Unihan의 `kHangul` 값으로 기계적으로 구하고(라이선스 허용적 — 미확인, 배포 전 확인), 동형동의인지 거짓 친구인지는 "한자음 한글 표기가 한국어 뜻에 들어 있는가" 규칙으로 1차 분류한 뒤, 경계 사례만 모델로 판정하고 거짓 친구 후보는 사람이 검수합니다. 같은 작업에서 **눈에 띄는 뜻 오류를 함께 고칩니다**(2.2).
- 왜 차별화인가: 기둥 1의 데이터 기반이고, 경쟁 앱이 하루 만에 따라 할 수 없는 자산입니다. 새 단어 순서를 정하는 데도 씁니다.
- 의존성: 일회성 모델 비용(8,130단어 중 경계 사례 수천 개 — 소액, 01 문서의 AI 원가 표에 반영), 검수 시간(거짓 친구 후보 수백 개 추정).
- 측정: 분류 정확도 표본 검수 95% 이상, 거짓 친구 목록 규모 확정.

**F3. 한자어 빠른 통과 모드 (M)**
- 내용: `kind = 동형동의`인 새 단어는 카드 앞면에서 뜻이 아니라 **읽기**를 묻습니다("図書館 — 어떻게 읽을까요?" → 공개 시 としょかん · 도서관). "읽기도 알아요"면 FSRS 첫 평가를 '쉬워요'로 처리해 바로 긴 간격으로 보내고, 모르면 일반 카드처럼 다룹니다. 원하면 같은 급수의 동형동의 단어를 몰아서 빠르게 훑는 "한자어 훑기" 세션(예: 30장)을 제공합니다. 학습 화면 구조와 답 버튼 3개는 바꾸지 않습니다(단순함 유지).
- 왜 차별화인가: "N2 단어 중 약 700개는 읽기만 확인하면 된다"는 구체적인 약속을 줄 수 있습니다. 영어권 앱은 구조적으로 할 수 없습니다.
- 의존성: F2. `buildQueue`·`nextNewIds`에 카드 종류 분기 추가.
- 측정: 급수당 새 단어를 다 만나는 데 걸린 일수(도입 전후), 빠른 통과 카드의 30일 기억률이 일반 카드보다 크게 떨어지지 않는지(5%p 이내면 성공).

**F4. 한·일 한자음 대응 힌트 (S~M)**
- 내용: 정답 공개 화면에서 한자별로 "館 관 → かん (ㄴ 받침 → ン)"처럼 대응 규칙을 한 줄로 보여 줍니다. 규칙 표는 받침·초성별 10~20개 경향 규칙으로 고정하고 AI 없이 결정적으로 계산합니다. 규칙에 맞지 않는 읽기에는 "예외"라고 표시합니다.
- 왜 차별화인가: 읽기 암기를 "한국어로 아는 것에서 끌어내기"로 바꿉니다. 기둥 1의 두 번째 절반입니다.
- 의존성: F2의 한국 한자음 데이터, 상용한자 음독 데이터(KANJIDIC2 — EDRDG 라이선스, 상업 사용 가능하나 출처 표기와 기부 권고 조건이 있음: [EDRDG 라이선스](https://www.edrdg.org/edrdg/license.html)).
- 측정: 힌트를 본 카드의 다음 복습 정답률이 힌트 없는 비슷한 카드보다 높은지.

**F5. 뜻 신고 + 검수 큐 (S) — 기본 요건**
- 내용: 정답 화면에 "뜻이 이상해요" 링크. 백엔드가 생기기 전에는 미리 채운 GitHub 이슈나 폼 링크로 받습니다.
- 왜: 차별화가 아니라 신뢰의 기본입니다. 기둥 1이 "한국어 뜻"을 핵심으로 내세우는 만큼 뜻 오류는 더 치명적입니다.
- 측정: 신고 건수와 처리 시간, 급수별 신고율.

## 6. 이름 — "루마" / "카사네" / "JLPT"

### 6.1 "루마" / "Luma" 충돌 점검 (2026-11-13, 검색 기반)

- **국내**: "루마"는 자동차 썬팅 필름 브랜드 LLumar의 한국 통칭으로 널리 쓰입니다(국내 선호도 상위 브랜드 — [숨고 블로그](https://soomgo.com/blog/car/자동차-썬팅-루마-썬팅-버텍스-필름-시리즈-등급-가격/)). 분야가 달라 상표 충돌 가능성은 낮아 보이지만 **"루마" 검색 결과가 썬팅으로 덮여** 있어 검색 유입에는 불리합니다. **KIPRIS(한국 상표) 조회는 하지 못했습니다 — 미확인.** 교육 분야(41류)·소프트웨어(9류) 등록 여부를 출원 전에 확인해야 합니다.
- **해외·앱스토어**: USPTO에 LUMA 상표가 여러 건 있습니다. Luma Labs(9·42류 등, AI 영상 앱 "Luma AI"), Luma Touch(영상 편집 앱), 출원 중인 건 등([Justia](https://trademarks.justia.com/owners/luma-labs-inc-4564551), [trademarkregistration.app](https://trademarkregistration.app/Trademark/Details/98703191)). App Store에는 AI 말하기 연습 앱 **"Luma Speak"**([App Store](https://apps.apple.com/app/id6759219746))가 있어 **언어 학습 분야와 겹칩니다.** 일본어 단어 앱 중 "Luma"라는 이름은 찾지 못했습니다.
- **판단**: 한글 "루마" 단독으로 국내 일본어 학습 앱에 쓰는 것은 법적 위험이 낮아 보이지만(미확인), 영문 "Luma"는 큰 회사들(Luma AI)과 같은 이름이라 **영문 표기·도메인·검색성이 약합니다.** 브랜드 자산은 이름보다 다루마 캐릭터에 있습니다.

### 6.2 "JLPT" 사용 제한

- 여러 비공식 학습 사이트가 "JLPT"와 "Japanese-Language Proficiency Test"를 국제교류기금(JF)과 일본국제교육지원협회(JEES)의 등록 상표로 표시하고 비제휴 고지를 답니다([예: gyanmirai 약관](https://www.gyanmirai.com/terms), [비공식 퀴즈 사이트](https://apps.graphtochart.com/quiz-jlpt-n2/)). **등록 원부(J-PlatPat·KIPRIS)는 직접 확인하지 못했습니다 — 미확인.**
- JLPT 공식 사이트의 이용 규정은 사이트 콘텐츠의 저작권에 관한 것으로, 정해진 범위 밖의 사용은 사전에 문의해 JF·JEES의 허가를 받으라고 합니다. 시험 문제의 저작권도 JF·JEES에 있습니다([사이트 정책](https://jlpt.jp/e/policy.html), [FAQ](https://www.jlpt.jp/e/faq/) — 검색 요약으로 확인, 직접 접속 불가). **앱 이름에 "JLPT"를 쓰는 데 대한 명시적 규정은 찾지 못했습니다.**
- **App Store 심사 지침 5.2.1**은 허가 없는 제3자 상표 사용과 오해를 부르는 이름을 금지하고, 제3자 상표가 들어가면 사용 권한 증빙을 요구할 수 있습니다. 실제 거절 사례는 대부분 권리자의 이의 제기에서 시작됩니다([App Review](https://developer.apple.com/distribute/app-review), [개발자 포럼 사례](https://developer.apple.com/forums/thread/734904)). 06 문서의 심사 요건과 함께 봐야 합니다.
- **현실**: 회독JLPT, JLPT Plus, "JLPT 오늘부터 일본어" 등 국내 앱 다수가 이름에 JLPT를 쓰고 있습니다. 당장 막히지는 않는 관행이지만, **브랜드 자체를 "JLPT 루마"로 만들면** 권리자가 이의를 제기할 경우 앱 이름·아이콘·도메인을 모두 바꿔야 합니다. 상표 등록도 어렵습니다(타인 상표를 포함한 이름).

### 6.3 추천

1. **브랜드는 "루마"(또는 다른 고유명)로, "JLPT"는 브랜드에 넣지 않습니다.** 스토어 표시명은 "루마 — JLPT 일본어 단어장"처럼 **시험 이름을 설명하는 용도로만** 씁니다. 아이콘·로고에는 JLPT 문자를 넣지 않습니다.
2. 앱 설명과 설정 화면에 비제휴 고지를 넣습니다: "이 앱은 국제교류기금·일본국제교육지원협회와 관계없는 비공식 학습 앱입니다. JLPT는 해당 기관의 상표입니다."
3. "카사네(重ね)"는 회독(겹쳐 보기)의 의미를 담은 좋은 이름이지만 한국어 화자에게 발음과 뜻이 바로 들어오지 않습니다. 코드 내부 이름으로 남기고 제품명은 루마로 통일하는 것을 추천합니다(저장 키 `kasane.state.v2`는 바꾸지 않음).
4. 출시 전에 KIPRIS에서 "루마"(9·41·42류)를 조회하고, 가능하면 상표를 출원합니다. 비용·절차는 07 문서나 별도 검토로 넘깁니다.
