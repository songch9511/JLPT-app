# 04. QA 보고서 — 자동화 테스트 도입과 버그 점검

작성: QA 담당 · 2026-11-13 · 대상 브랜치: 현재 작업 트리(커밋 안 함)

## 결론

1. **테스트 기반을 깔았습니다.** 단위 테스트 78개(Vitest)와 E2E 테스트 34개(Playwright, 휴대폰 화면)가 모두 통과합니다. `npm test`, `npm run test:e2e`로 돌리고, PR마다 타입 검사·단위 테스트·빌드를 도는 CI(`.github/workflows/ci.yml`)를 추가했습니다.
2. **버그 11개를 고쳤고, 고친 버그마다 수정 전 코드에서는 실패하고 수정 후에는 통과하는 테스트가 있습니다.** 그중 크게 다칠 수 있는 것은 셋입니다.
   - 기기 시계가 뒤로 가면 학습 화면이 흰 화면이 됨
   - 깨진 백업 파일을 가져오면 앱이 다시 열리지 않음
   - 탭 두 개를 열어 두면 한쪽 탭이 다른 탭의 학습 기록을 지움
3. **고치지 않은 것 중 먼저 결정할 것은 세 가지입니다.**
   - 앱 업데이트 직후 열려 있던 화면에서 AI 기능이 실패함(O1)
   - 에러 화면이 없어서 어떤 오류든 흰 화면이 됨(O2)
   - 카드 ID가 단어 목록의 순번이라, 커리큘럼 데이터를 다시 만들면 기존 기록이 엉뚱한 단어에 붙음(O4)
   맨 끝 "결정이 필요한 것"에 추천안과 함께 적었습니다.
4. **여기서 확인할 수 없었던 위험**은 실제 iOS Safari(7일 데이터 삭제 정책, 음성 재생, 백업 내보내기)와 실제 Anthropic API 호출입니다. API 요청 모양은 현재 공식 문서와 맞는 것까지 확인했습니다(6절).

## 1. 실행 방법

| 명령 | 내용 | 시간(로컬) |

- `@playwright/test`는 설치된 Chromium(빌드 1243)과 맞도록 **1.63.0으로 고정**했습니다. 브라우저가 다르면 `PW_CHROMIUM=/경로/chrome`으로 실행 파일을 지정할 수 있습니다.
- E2E는 Playwright 가짜 시계로 2026-11-13 09:00(서울)에서 시작합니다. 같은 실행을 세 번 반복해도(`--repeat-each=3`, 99/99) 결과가 같았습니다.
- **CI에는 E2E를 넣지 않았습니다.** 이 환경에서 GitHub 러너로 돌려 볼 수 없었고, 러너에서는 브라우저를 매번 내려받아야 합니다. 로컬에서는 안정적이므로, 러너에서 한 번 통과하는 것을 확인한 뒤 별도 job으로 넣기를 권합니다.

### 테스트가 다루지 않는 것

- React 컴포넌트 단위 테스트는 없습니다. 화면은 E2E로만 봅니다.
- 다루마 그림, 히트맵, 여정 스크롤 같은 **시각 요소**의 픽셀 비교는 없습니다(디자인 작업이 곧 바꿀 예정이라 지금 기준선을 두면 소음만 늘어남).
- 서비스 워커·오프라인은 E2E에서 막아 두었고(`serviceWorkers: 'block'`), 탐색 테스트로 한 번만 확인했습니다(3절).
- 발음(`speechSynthesis`)과 자동 재생, 실제 API, 실제 iOS 기기.
- `scripts/build-data.mjs`(데이터 생성).
- 테스트 코드 자체는 타입 검사 대상이 아닙니다(`@types/node`가 없음). 필요하면 추가하면 됩니다.

## 3. 탐색 테스트에서 본 것(문제 없음)

- **규모**: 8,130단어를 모두 시작하고 1년치 로그가 있는 상태(저장 크기 약 1.7MB)에서 홈 로드 170ms, 답변 클릭부터 다음 카드까지 약 80ms(답변 처리와 렌더 약 20ms).
- **320px 폭**: 홈·학습·단어장·급수·설정·단어 시트 모두 가로 스크롤 없음. 가장 긴 표기(「それはいけませんね (かん)」)도 줄바꿈으로 들어감.
- **잘못된 해시 경로**(`#/level/9`, `#/nope`, `#%%%` 등)는 홈으로 갑니다. 유효한 경로 뒤에 붙은 부분은 무시합니다.
- **reduced motion**: 설정 시 홈과 완료 화면에서 실행 중인 애니메이션 0개.
- **오프라인 시작**(빌드본, 서비스 워커 설치 후 네트워크 차단): 홈·학습 카드·전체 단어 검색 모두 동작.
- **하루 새 단어를 하루 도중에 바꾸기, 급수 소진, 지난 시험일**: 오류 없이 처리(단위·E2E 테스트로 고정).
- **입력란에 포커스가 있을 때의 키 처리**: 전역 단축키는 학습 화면에만 있고, 학습 화면에는 입력란이 없습니다. 단어 시트의 Esc는 의도대로 동작합니다.

## 6. 여기서 확인하지 못한 위험

- **실제 Anthropic API**: E2E는 응답을 흉내 낸 것입니다. 요청 모양은 현재 공식 문서(2026-11 기준 Claude API 스킬 문서로 확인)와 맞습니다: 모델 `claude-opus-5-5`, 베타 `server-side-fallback-2026-07-01` + `fallbacks: "default"`, `output_config: {effort, format}`, `stop_reason === "refusal"` 처리. 실제 키로 호출해 보지는 않았습니다(비용·키 없음). Opus 5.5의 effort 기본값은 `medium`이고 이 앱은 `low`를 명시합니다. 브라우저에서 키를 직접 쓰는 구조 자체의 문제는 01·07 문서 범위입니다.
- **GitHub Pages 배포본의 서비스 워커 갱신**: 빌드본을 로컬 서버로 흉내 냈을 뿐 실제 Pages 캐시 헤더는 확인하지 못했습니다.
- **저사양 안드로이드 성능**: 데스크톱 Chromium 기준 수치입니다.
- **실제 시간대 이동(해외여행)과 OS 시계 변경**: 로직은 단위 테스트로 확인했고(B1), 실기기는 미확인입니다.

## 결정이 필요한 것

1. **앱 업데이트 방식(O1).** 추천: `registerType: 'prompt'`로 바꾸고 "새 버전이 있어요 · 새로고침" 알림을 띄우기. 학습 중 갑자기 새로고침되지 않고, AI 청크 오류도 사라집니다. 대안인 "자동 새로고침"은 학습 도중에 화면이 바뀔 수 있어서 권하지 않습니다.
2. **오류 화면(O2)과 저장 실패 경고(O3).** 추천: 최상위 Error Boundary에 "문제가 생겼어요 · 백업 내보내기 · 다시 시도" 화면을 두고, 저장이 실패하면 한 번 배너로 알리기. 흰 화면 대신 사용자가 기록을 빼낼 수 있게 됩니다. 05 UX 작업과 함께 진행합니다.
3. **카드 ID 체계(O4).** 추천: 커리큘럼 데이터를 바꾸기 **전에** 단어마다 바뀌지 않는 ID(예: 표기+읽기의 해시, 또는 원본 덱의 ID)를 두고, 기존 `급수-순번` 기록을 새 ID로 옮기는 변환을 한 번 넣기. 이 결정 없이 단어 목록을 다시 만들면 기존 사용자 기록이 조용히 망가집니다.
4. **더블 탭 잠금 시간(B5).** 추천: 지금 값(350ms)을 유지. 너무 빠른 답이 반응 없이 무시되는 것이 불편하다는 의견이 나오면 250ms까지 낮출 수 있습니다.
5. **하루의 경계.** 지금은 자정이 기준이라 밤 12시 넘어 공부하면 다음 날로 기록되고 연속 학습 계산도 그 기준을 따릅니다. 추천: Anki처럼 새벽 4시를 경계로 하기. 03 커리큘럼 설계와 함께 정하세요.
6. **시험일이 지난 뒤.** 지금은 "시험 종료"만 보이고 날짜는 그대로입니다. 추천: 시험일 다음 날 홈에서 다음 시험일로 넘길지 한 번 묻기.
7. **목표 급수의 단어를 모두 만난 뒤의 퀘스트.** "새 단어 N개 만나기"를 영영 달성할 수 없습니다. 추천: 다음 급수를 권하거나 그 퀘스트를 복습 퀘스트로 바꾸기(03).
8. **E2E를 CI에 넣을지.** 추천: GitHub 러너에서 한 번 통과를 확인한 뒤 PR 필수 검사가 아닌 별도 job으로 추가하고, 2주 동안 불안정하지 않으면 필수로 올리기.
