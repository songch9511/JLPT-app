# 08. 단어 데이터 파이프라인: 빈도 순서 · 단어 유형 태그

작성 2026-11-13 · 근거 문서: `03-curriculum-dashboard.md` §2.1–2.4, `02-differentiation.md` F2–F4 · 확인일(출처·라이선스) 2026-11-13

## 결론과 추천

1. **빈도 출처는 wordfreq 3.1.1(일본어)로 정했고, 8,130단어 전부에 점수와 급수별 소개 순서를 만들었다.** JMdict(우선순위 태그·"보통 가나 표기"·품사·이표기)를 보조로 써서 동형이의 표기, 옛 오쿠리가나, 동사 활용형 분산을 보정했다. wordfreq 데이터에 한 단어로 직접 맞은 비율은 급수별 91~97%다. 나머지는 복합어 추정이고, 아무 데서도 못 찾은 단어는 5개뿐이다(최저값으로 맨 뒤에 둔다, 버리지 않음).
2. **라이선스 결과: 파생 빈도·순서 데이터는 CC BY-SA 4.0이다.** 상업 앱에 넣어도 되지만 (a) 앱 "정보" 화면과 문서에 wordfreq(OpenSubtitles 등 원출처 포함)와 EDRDG(JMdict/KANJIDIC) 표기가 필요하고, (b) 이 열을 담은 데이터 파일은 CC BY-SA로 배포해야 한다(다른 사람이 가져다 써도 막을 수 없다). 앱 **코드**에는 영향이 없다. 결정 항목 1.
3. **소개 순서는 순수 빈도순이다**(동점이면 JMdict 우선순위, 그다음 기존 idx). 단어 유형과 섞지 않는다. 이유는 §2.4.
4. **단어 유형 태그는 4개 필드로 정했다**: `k`(S/F/J/N/M/L/K), `sk`(한국 한자음), `ff`(거짓 친구 설명), `rt`(읽기 유형 on/kun/mix/irr). 03 문서의 S/F/N/L/K에 **J(한국어에 없는 음독 한자어)와 M(혼종)** 을 더하고, "뜻 대신 읽기를 물을지"는 `k === 'S'` 하나로 정한다. `rt`는 F4 한자음 대응 힌트를 켤지 정한다.
5. **기계 사전 작업으로 사람이 볼 몫을 줄였다**: 가나만 쓴 단어 1,199개(L 525, K 674)는 자동 확정, 한자 단어 6,931개에는 한국 한자음 후보(99.8%)와 읽기 유형 후보, 유형 힌트를 붙였다. 한국 한자음은 Unihan `kHangul`(Unicode 라이선스)을 우선 쓰고, 일본 신자체(図·駅·売 등 약 230자)만 KANJIDIC2로 채웠다.
6. **라벨링 키트 완성**: 청크 35개(N5 4 · N4 3 · N3 9 · N2 8 · N1 11, 약 250단어, N5-1은 60단어 시범), 안내서 `data/tags/LABELLING.md`, 검사기 `scripts/enrich/validate-tags.mjs`. 시범 청크 `data/tags/n5-1.json`을 직접 라벨링해 검사기를 통과시켰다.
7. **`build-data.mjs --extras`** 가 기존 4열 뒤에 `o, f, k, sk, ff, rt`를 붙인다. 기본 실행은 지금과 똑같다. `public/data/`는 이번 작업에서 다시 만들지 않았다.

## 2. 빈도 순서

### 2.1 산출물

| 파일 | 내용 |
| --- | --- |
| `data/freq/n{l}.json` | `{ "<idx>": f }`, f = round(Zipf × 10), 10–80. 0은 없다(최저값 10) |
| `data/freq/n{l}.src.json` | `{ "<idx>": "w"|"h"|"c"|"k"|"r"|"j"|"z" }` 점수를 얻은 방법 |
| `data/freq/order-n{l}.json` | 소개 순서: idx의 순열(0..n−1). 앞이 먼저 |
| `data/freq/coverage.json` | 방법별 개수 |
| `data/freq/NOTICE.md` | 출처·라이선스 |

### 2.2 까다로운 표제어 처리 (`scripts/enrich/forms.mjs`)

- `～`·`〜` 접사: 지우고 남은 부분으로 찾는다(`～匹` → 匹, `お～` → お). 가운데 `～`는 부분을 띄어 찾는다(`いくら～ても`).
- 괄호 주석: 모두 지운다(`(かん)`, `(な)`, `(する)`, `(をつかむ)`, `(はなを～)`).
- 여러 표기: `;` `、` `,` 와 단어 사이 공백으로 나누고 **가장 높은 값**을 쓴다(`丸い; 円い`, `こうよう もみじ`). 여기에 JMdict가 같은 항목·같은 읽기에 등록한 다른 한자 표기도 더한다(옛 오쿠리가나 `終る` → `終わる`, `引っ繰り返す` → `ひっくり返す`).
- 예외 3개는 표로 직접 지정(`×` → ばつ, `〜 (まる) ごと` → 丸ごと, `我`).
- 가나 단어: 가나 그대로 찾는다.

### 2.3 점수 규칙 (`scripts/enrich/freq.py`, 순서대로 시도)

| 코드 | 규칙 |
| --- | --- |
| `w` | 표기(또는 이표기)가 wordfreq에 한 토큰으로 있음. **한자 동사·い형용사는 활용 표면형을 합산**(書く+書か+書き+書け+書こ+書い, する동사 포함). wordfreq는 형태소 표면형을 세므로 이렇게 하지 않으면 동사가 명사보다 체계적으로 낮게 나온다 |
| `h` | `w`인데 같은 표기를 여러 단어가 나눠 씀: 上(うえ/かみ/じょう/うわ), 가나 より(조사/縒り), 낱자 出(出る의 出た). JMdict 우선순위 가중치(공통어 1, 기타 태그 0.3, 없음 0.1, nf01–12는 ×2, 가나로 잘 안 쓰는 한자 단어는 가나 검색 때 ×0.2)로 몫을 나눠 Zipf + log10(몫). 가나 동형어는 영어 뜻과 JMdict 뜻풀이 단어 겹침으로 어느 항목인지 고른다 |
| `c` | MeCab이 여러 토큰으로 나누는 말(何でも, いただきます): wordfreq 합성값에서 토큰 경계마다 0.5, 최대 1.0을 뺀다(wordfreq는 중국어에만 경계당 1을 뺀다) |
| `k` | JMdict가 첫 뜻에 "보통 가나 표기"를 단 단어이고 가나 철자가 다른 흔한 단어와 겹치지 않으면, 가나 철자 빈도가 더 클 때 그 값(唯 → ただ, 沢山 → たくさん) |
| `r` | 표기를 못 찾으면 읽기 빈도 × 0.8(03 문서 규칙). 흔한 동음어가 있으면 쓰지 않음 |
| `j` | 그래도 없으면 JMdict nf 구간의 wordfreq 중앙값(데이터로 보정) |
| `z` | 최저값 Zipf 1.0(f=10) — "wordfreq 목록 하한보다 드묾" |

`r`·`j`는 이표기 보강 뒤 현재 데이터에서 0건이지만 단어 목록이 바뀔 때를 위해 남겼다. 같은 입력이면 같은 출력이다(두 번 실행해 바이트 단위로 같음을 확인).

### 2.4 순서 규칙과 "섞을지" 결정

정렬 키: `f` 내림차순 → JMdict 우선순위(news1/ichi1/spec1/spec2/gai1 = 1, 다른 태그 = 2, 없음 = 3) → idx 오름차순. idx 자체가 고정 시드 셔플이므로 동점 묶음 안은 안정적인 무작위 순서다.

**빈도만 쓰고 다른 것과 섞지 않는다.** (1) 03 문서 §2.1의 명세가 이 순서다. (2) 유형(S 먼저 등)과 섞으면 라벨링이 진행될 때마다 순서가 바뀌고, 이미 시작한 사용자의 다음 단어가 흔들린다. S 단어의 값싼 비용은 03 §2.4의 "새 단어 비용" 계수로 하루 계획에서 반영된다. (3) 의미 범주가 몰리는 문제(같은 뜻 연속)는 데이터가 아니라 앱의 큐 규칙(03 §5.2 4번: `ko` 첫 뜻이 같은 단어 연속 금지)이 맡는다. (4) "Zipf×10 정수"로 0.1 단위 묶음이 생기므로 근소한 차이에 과적합하지 않는다.

## 3. 단어 유형 태그

### 3.1 스키마 (`scripts/enrich/tags-schema.mjs`가 기준)

| 필드 | 값 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `k` | `S` 동형동의 한자어 · `F` 거짓 친구 · `J` 일본 한자어(한국어에 없음·드묾·고어) · `N` 고유어(훈독) · `M` 혼종·기타(음훈 혼합·숙자훈·한자+가타카나) · `L` 외래어 · `K` 가나 표기어 | 모든 단어 | 판정 순서: 먼저 "같은 한자 한국어 단어를 알아보는가"(S/F), 아니면 출신(J/N/M), 한자 없으면 L/K |
| `sk` | 한글 음절만, 한자 1자 = 1음절, 두음법칙 적용(접미사 제외) | S·F·J 필수, N·M 선택, L·K 금지 | 한국 한자음(産業 → 산업, 挨拶 → 애찰) |
| `ff` | 한국어 한 줄, 60자 이내, 가나·한자 금지 | F 필수, 그 외 금지 | 뜻 차이(工夫: "한국어 '공부'(학습)와 달리 '궁리·고안'") |
| `rt` | `on` · `kun` · `mix` · `irr` | 한자 있는 단어 필수, 가나 단어 금지 | 읽기 유형. F4 한자음 대응 힌트는 `on`일 때만 |

03 문서와의 차이: **J를 따로 둔다**(N3~N1 한자어의 상당수가 여기 속하고, 뜻 카드가 필요하지만 F 경고는 부적절하며, 음독이라 한자음 힌트는 쓸모 있다). **K는 03과 같은 뜻(가나 표기)**, N은 "한자로 쓴 고유어"로 좁혔다. **"뜻 대신 읽기를 묻는다" = `k === 'S'`** 하나로 판정한다. 그래서 S의 정의를 "한국 성인이 한자를 보고 한국어 단어를 떠올려 뜻을 바로 아는가"로 잡았다(읽기 방식과 무관: 薬 くすり도 S). 읽기 방식은 `rt`가 따로 갖는다. 판정 규칙·예시 33개는 `data/tags/LABELLING.md`.

### 3.2 기계 사전 작업 (`scripts/enrich/prepass.mjs` → `data/tags/prepass/n{l}.json`)

단어마다 `{ core, hk, auto, sk:[후보], rt, hint }`. `auto`(L/K)는 확정값, 나머지는 후보다.
- 한국 한자음 후보: `data/hanja/kanji.tsv`(Unihan kHangul의 교육용(E) 음 우선 → KANJIDIC2 보충)에서 글자별 음을 잇고 두음법칙·렬/률 규칙을 적용, 최대 8개.

## 4. 다시 만드는 법


빌드(`build-data.mjs`)에는 Python이 필요 없다. 산출물은 모두 저장소에 커밋하는 파일이다. 단어 목록(`data/raw`)이 바뀌면 freq → prepass 순서로 다시 돌리고, `chunks.json`은 이미 라벨링 중인 청크를 흔들지 않도록 손대지 않는다(새 단어는 새 청크로).

## 5. 앱 쪽 엔지니어가 알아야 할 것

**행 형식** (`--extras`): `[w, r, ko, en, o, f, k?, sk?, ff?, rt?]`
- 앞 4열과 행 순서(=idx)는 그대로다. 단어 ID `<level>-<idx>`는 바뀌지 않는다.
- `o`(number): 급수 내 소개 순서 0..n−1(순열). `nextNewIds`는 idx 대신 `o` 오름차순으로 고른다. **`o`를 ID로 쓰지 말 것.**
- `f`(number): round(Zipf×10), 10–80. "고빈도 훑기" 같은 기능의 임계값에 쓸 수 있다(예: f ≥ 45).
- 태그 4열은 **라벨링된 단어에만** 있다. 행 끝의 빈 열은 잘라내므로 행 길이는 6~10이다. 중간의 빈 값은 `''`. 파싱 예: `const [w, r, ko, en, o, f, k = '', sk = '', ff = '', rt = ''] = row`.
- `k === ''`(미라벨)은 지금과 같은 뜻 카드로 처리한다. `k === 'S'`만 읽기 전용 카드(03 결정 5: S 정밀도 95% 검수 전에는 켜지 말 것). `k === 'F'`면 빨간 칩 + `ff`. `rt === 'on' && sk`일 때만 한자음 대응 힌트.
- 크기: 5개 파일 합계 530KB → 591KB(+11%, 태그가 다 붙으면 더 는다. 추정 +25%).
- `src/data.ts`의 `COUNTS`는 바뀌지 않는다. `Word`에 `o, f, k, sk, ff, rt`를 선택 필드로 더하면 된다.
- 정보 화면에 §1의 출처 표기를 넣어야 한다(EDRDG 조건).

## 6. 알려진 약점

- **wordfreq는 표면형 빈도다.** 동형어 보정(h)은 JMdict 태그로 몫을 나누는 근사다. 가나 동형어(とって=손잡이 vs ～にとって), 같은 표기의 다른 읽기(～中 ちゅう/じゅう)는 여전히 부풀거나 같은 값을 받는다.
- 가중치·벌점 상수(0.5/경계, 1/0.3/0.1, ×2, ×0.2)는 결과를 눈으로 보며 정했다. 기준 자료(BCCWJ 등)와 대조해 조정하지 않았다(BCCWJ는 상업 조건 미확인으로 받지 않음).
- 가나로만 쓴 동사(なる, できる)는 활용형을 합산하지 않는다(なら·なっ 같은 표면형이 다른 말과 겹쳐서). 기본형만으로도 충분히 높게 나온다.
- 코퍼스가 자막·웹·SNS 중심이라 회화어가 강하고 신문·시험 문어가 약하다. 데이터는 2021년 스냅숏이다. JMdict는 2021년, KANJIDIC2는 2008년판이다.
- 한국 한자음 후보는 글자별 대표음이라 단어별 관용음(楽 → 악만 있음, 音楽의 '악'은 맞지만 快楽 '락'은 없음)을 놓친다. 라벨러가 고친다.
- 사전 힌트(S/J/N/M)의 정확도는 측정 전이다. `ko`가 모델 번역이라 S 힌트도 그 오류를 물려받는다.
- 라이선스 원문 일부(EDRDG 현재 페이지, unicode.org)는 이 세션에서 직접 열지 못했다(패키지 동봉본·SPDX 사본·검색 결과로 확인).
